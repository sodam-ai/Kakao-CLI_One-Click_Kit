# 카카오톡 키트 (Kakao-CLI One-Click Kit)

[한국어](README.md) · [English](README.en.md)

> **현재 상태: 개발 중입니다 (전체 13단계 중 1~6단계 완료, 7단계 방 열기는 명령까지 연결, 9단계 내보내기는 부품까지 완성).**
>
> 지금 연결된 명령은 `kakao version`·`help`·`status`·`rooms`·`open`·`read`·`search`·`send` 입니다. 그중 카카오톡 없이 바로 되는 것은 `version`·`help`·`status`·`rooms list` 이고, `open` 은 허용한 방을 열어 창 제목을 확인하고 닫는 명령으로 실제 카카오톡에서 1회만 확인했습니다. `read`·`search` 는 보관된 내보내기 파일이 있어야 하는데 그 파일을 만드는 `export` 명령이 아직 없어서 쓸 자료가 없고, **`send` 는 잠겨 있어 아무것도 보내지 않습니다.** 대화 저장(`export`)·번호 메뉴·업데이트·제거는 **아직 명령으로 쓸 수 없습니다.** 카카오톡 화면에서 대화를 저장해 오는 부분(`Ctrl+S`)은 부품(`Exporter.ps1`)까지 만들었지만, 이 부품을 실제 카카오톡에서 돌려 본 적은 없고 명령에도 연결하지 않았습니다. 이 문서는 "지금 되는 것(✅)"과 "만들 예정인 것(⏳)"을 처음부터 끝까지 구분해서 적습니다.
>
> **비공식 도구**입니다. 카카오톡을 만든 회사(주식회사 카카오)와 아무 관계가 없습니다. 사용에 따른 책임은 사용자에게 있습니다. 사용하기 전에 반드시 [17장 법률·저작권·라이선스](#legal)를 읽어 주세요.

문서 기준일: 2026-11-16 · 기준: 작업 1~6 완료 + 7단계 방 열기(`kakao open` 명령 연결) + 9단계 보관·읽기·검색·내보내기 부품 + 보낸 글 확인 판정 · 자동 시험 539개 · 라이선스: Apache License 2.0 · 이 문서는 컴퓨터를 처음 다루는 분도 따라 할 수 있도록 썼습니다.

- ✅ = 지금 실제로 됩니다. ⏳ = 아직 안 됩니다(만들 예정).
- 이 문서의 `kakao` 는 실제로는 `.\kakao.cmd` 라고 입력합니다. 이유는 [6장](#run)에 있습니다.

## 1. 이 프로젝트는 무엇인가요?

**한 줄 설명:** 윈도우(Windows)용 카카오톡 PC 앱을 명령 한 줄 또는 `시작.bat` 더블클릭으로 다룰 수 있게 만드는 도구 모음입니다.

### 왜 필요한가요?

카카오톡에는 프로그램이 직접 쓸 수 있는 공식 명령 기능(API)이 없습니다. 그래서 이 키트는 사람이 키보드로 하는 동작(붙여넣기 `Ctrl+V`, 전송 `Enter`, 대화 저장 `Ctrl+S`)을 **대신 눌러 주는 방식**으로만 동작합니다. 사용자는 두 부류를 생각하고 만들고 있습니다.

1. 코딩을 모르는 사람: 번호를 누르는 한글 메뉴 화면 (⏳ 예정)
2. AI 도우미(예: Claude Code): `kakao <명령> --json` 형태의 명령줄 (⏳ 예정)

### 만들려는 기능 (목표)

- 내가 허용한 방에만 메시지 보내기
- 대화 읽기: 카카오톡의 공식 "대화 내보내기" 기능을 사용
- 저장해 둔 대화에서 키워드 검색
- 환경 점검, 설치·업데이트·제거
- 오류가 나면 비개발자도 이해할 수 있는 한글 설명과 기록(로그)을 남김
- 제거해도 카카오톡 앱과 대화 데이터는 건드리지 않음

### 하지 않는 것 (비목표)

- 카카오톡 대화 저장소(DB)를 해독하거나 앱을 분석·변조하는 방식: 이용약관과 충돌할 수 있어 쓰지 않기로 확정했습니다.
- 실시간 감시, 자동 답장 봇, 여러 방에 한꺼번에 보내기
- 사진·파일 같은 글자가 아닌 메시지의 읽기·보내기
- 카카오톡 외의 메신저, macOS(맥), 스마트폰

### 참고한 것

macOS 전용 오픈소스 도구(이름: kakaocli)가 있지만 맥에서만 동작해서 윈도우에서는 쓸 수 없었습니다. 그래서 같은 목적을 **윈도우용으로 처음부터 새로 만들었고, 그 도구의 코드를 가져다 쓰지 않았습니다.**

### 사용자가 정한 4가지 약속

| 약속 | 지금 상태 |
|---|---|
| 관리자 권한(UAC) 창이 절대 뜨지 않는다 | ✅ 관리자 권한을 요청하는 코드가 없습니다. 레지스트리·서비스·작업 스케줄러 등록, Program Files 쓰기도 없습니다(자동 시험이 검사). |
| 영어 메뉴는 한글로 쓰거나 한글과 영어를 함께 쓴다 | ✅ 모든 안내 문구를 한글 문구 사전 한 곳에서 만듭니다. 윈도우의 영어 `pause` 문구도 한글로 바꿨습니다. 메뉴 화면 자체는 ⏳ 예정입니다. |
| 메뉴에 들어가는 단계를 최소로 한다 | ⏳ 설계됨: 숫자 한 번만 누르면 실행, 보내기는 입력 4번 이내. 메뉴는 아직 없습니다. |
| 메뉴는 간단하면서 자세하게 | ⏳ 설계됨. 메뉴는 아직 없습니다. |

## 2. 현재 상태: 되는 것과 아직 안 되는 것

개발은 13단계로 나뉘어 있고 지금까지 1~6단계를 끝냈으며 7단계는 명령(`kakao open`)까지 연결했고, 9단계는 보관·읽기·검색 부품과 내보내기 부품(`Exporter.ps1`)까지 만들었습니다. 8단계(보내기)는 판정 부품까지만 있고 잠겨 있습니다. 표의 "부품 완료"는 **그 기능의 부품(함수)이 만들어졌고 자동 시험을 통과했지만, 사용자가 부를 수 있는 명령으로는 아직 연결되지 않았다**는 뜻입니다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 시작 틀: 한글 깨짐 방지, 관리자 권한 없음, `시작.bat` 임시 화면, `kakao version` | ✅ 완료 |
| 2 | 설정·허용 방 목록·사용 동의 | ✅ 부품 완료 |
| 3 | 기록(로그)과 오류 보고서 | ✅ 부품 완료 |
| 4 | 키 입력 계층과 안전장치("문지기") | ✅ 부품 완료 (실제 카카오톡에 입력하는 시험은 ⏳) |
| 5 | 클립보드 보존과 복원 | ✅ 부품 완료 |
| 6 | 내보내기 파일 읽기(파서) | ✅ 부품 완료 |
| 7 | 방 열기 | ✅ 부품 완료, `kakao open` 명령 연결됨(실제 확인은 1회뿐, 안정성은 미확인). 아래는 확인 이력입니다. 실제 카카오톡으로 확인한 것: 검색 결과가 방 이름 하나뿐인지 화면 글자 읽기로 판정(실제 화면으로 확인하고 고침), 방 열기·닫기(100% 모니터에서 첫 결과 더블클릭 → 새 창 제목 확인 → 키트가 연 창만 닫기, 1회 통과). 2026-11-12 S5 1회 통과(카카오톡 26.9.2.5342, 150% 모니터의 창 588x753·배율 1.5, 오픈채팅 화면, 나 혼자 있는 시험용 방): `Ctrl+F` → 방 이름 붙여넣기 → 결과 1건 확인 → 첫 줄 더블클릭 → 새 창 제목 확인 → 키트가 연 창만 닫기가 8.6초에 끝났고 닫은 뒤 창 목록이 시작 때와 같았습니다. 한 번뿐이며 다른 탭·100% 모니터·일반 방(1:1·단체방)은 시험하지 못했습니다. 150% 모니터에서 창 배율이 100%로 잘못 읽히던 결함은 고쳤고 이 시험으로 실제 동작도 확인했습니다(12.3의 10번) **(2026-11-15 갱신)** 방 열기는 화면 글자 읽기(OCR)와 고정 픽셀 위치를 더는 쓰지 않고, 카카오톡 메인 창의 화면 이름(구조)으로 확인합니다. 이 PC의 100% 배율(창 392x502) 채팅 탭에서 `Ctrl+F` → 방 이름 붙여넣기 → 검색 열림 확인 → `Enter`(200ms) → 새 창 제목이 글자 그대로 일치 → 입력란 포커스 `True` 확인 → 키트가 연 창만 닫기가 1회 통과했습니다. 반복 사용을 막던 검색창 잔류는 `Esc` 한 번(메인 창에서 검색이 열려 있을 때만)으로 닫는 것을 확인했습니다. 150% 모니터·오픈채팅 탭·친구 탭·일반 방은 아직 확인하지 못했습니다 |
| 8 | 메시지 보내기 | ⏳ 예정 (9단계 다음에 만들고, 시작 전에 사용자의 별도 승인을 받음) |
| 9 | 내보내기·읽기·검색 | ⏳ 일부 부품 완료 (8단계보다 먼저 만듦). 내보내기 파일 보관(방마다 최근 3개·30일)·읽기·검색 부품은 가짜 파일로 시험을 통과했습니다. 카카오톡에서 `Ctrl+S` 로 저장 → 파일 생성 → 파서로 읽기까지는 2026-11-15 에 실제 카카오톡에서 1회 확인했습니다(D1·D2, 14장). 이 과정을 키트 코드로 묶은 내보내기 부품(`Exporter.ps1`)은 2026-11-16 에 만들어 가짜 부품으로만 시험했고(실제 카카오톡에서 이 부품을 돌려 본 적은 없습니다), 명령(`export`)과 보내기에는 아직 연결하지 않았습니다 |
| 10 | 상태 점검, 카카오톡 버전 확인, 로그인 안내, 미검증 버전 잠금 | ⏳ 예정 |
| 11 | 명령 분배기 완성, 번호 메뉴, `help` | ⏳ 예정 |
| 12 | 첫 실행 동의, 업데이트, 제거 | ⏳ 예정 |
| 13 | 처음부터 끝까지 인수 시험, 사용 설명서 최종본 | ⏳ 예정 |

**작업 순서 변경 (2026-10-30 사용자 승인):** 계획서에는 보내기(8단계) 다음에 읽기(9단계)였지만, **읽기를 먼저 만들고 보내기를 나중에 만듭니다.** 이유는 세 가지입니다. ① 읽기가 없으면 보낸 메시지가 정말 갔는지 확인할 수 없어서, 설계서 13.7 이 정한 결과 3가지(확인됨·실패·불명) 중 '불명'만 나오게 됩니다. ② 읽기의 파서는 이미 만들어져 있고, 합성한 가짜 대화 파일로 시험할 수 있습니다. ③ 지금까지 실제 카카오톡에 보내 본 키는 `Ctrl+V` 뿐이라, `Enter` 를 처음 누르는 곳이 상대에게 가는 메시지 전송이 아니라 파일 저장 창이면 실수의 피해가 작습니다.

## 4. 다운로드와 설치 방법

### 다운로드 방법

**소스는 GitHub의 비공개(private) 저장소 `Kakao-CLI_One-Click_Kit` 에 있습니다.** 아직 공개 저장소가 아니라서 접근 권한이 있는 사람만 받을 수 있고, 누구나 내려받는 공개 주소는 없습니다. 접근 권한이 있다면 둘 중 한 가지로 받습니다.

- 방법 가: GitHub 저장소 페이지의 초록색 `Code` 버튼을 누르고 `Download ZIP` 을 눌러 압축 파일을 받습니다(영어 화면 기준).
- 방법 나: GitHub CLI(`gh`)가 설치되어 있다면 `gh repo clone <소유자>/Kakao-CLI_One-Click_Kit` 을 실행합니다. `<소유자>` 는 저장소를 만든 GitHub 계정 이름입니다.

USB나 압축 파일로 폴더를 직접 받았다면 바로 아래 순서로 설치합니다.

### 설치 방법 (폴더 복사)

1. 압축 파일(.zip)이면 **먼저 완전히 풀어 주세요.** 파일을 우클릭해서 "모두 압축 풀기"(영어 윈도우: Extract All)를 고릅니다. 압축 파일 안에서 바로 실행하면 일부 파일만 임시로 풀려 실패합니다.
2. 풀어 둔 폴더를 원하는 곳에 둡니다. 예: `D:\KakaoKit`. 짧은 영문·숫자 이름을 권장합니다. 폴더 이름에 `%PATH%` 처럼 `%이름%` 꼴은 넣지 마세요(15장의 알려진 한계).
3. 폴더 안에 `시작.bat`, `kakao.cmd`, `src` 폴더가 보이면 준비가 끝난 것입니다.
4. 설치 프로그램도, 회원가입도, 로그인도 없습니다.

### 업데이트 방법

지금은 업데이트 명령이 없습니다(`update` 는 ⏳ 예정). 새 폴더를 받았다면 기존 폴더를 새 폴더로 바꿔 쓰면 됩니다. 저장소를 `gh repo clone` 으로 받았다면 그 폴더 안에서 `git pull` 을 실행해 최신으로 맞출 수도 있습니다. 설정과 기록을 저장하는 기능이 연결된 뒤에는 그것들이 사용자 폴더의 `%LOCALAPPDATA%\KakaoKit` 에 따로 있어서, 프로그램 폴더를 바꿔도 보존됩니다(⏳).

### 제거 방법

**폴더를 삭제하면 끝입니다.** 지금 버전은 폴더 밖에 아무것도 만들지 않습니다. 레지스트리, 바탕화면 바로가기, 시작 메뉴, PATH, 작업 스케줄러 모두 건드리지 않습니다(코드 검색으로 확인했고, 이 PC에 `%LOCALAPPDATA%\KakaoKit` 폴더가 없는 것도 확인했습니다). 앞으로 설정을 저장하는 기능이 연결되면 그 폴더가 생길 수 있고, `uninstall` 명령이 안내합니다(⏳). 어떤 경우에도 카카오톡 앱과 대화 내용은 건드리지 않습니다.

## 5. 빠른 시작 (5분)

지금 할 수 있는 전부입니다. 키트가 제대로 놓였는지 확인합니다.

1. 탐색기에서 키트 폴더를 엽니다.
2. `시작.bat` 을 더블클릭합니다.
3. 검은 창에 아래와 같은 글자가 나오면 **정상**입니다. (앞뒤의 빈 줄은 생략했습니다.)

```text
  카카오톡 키트 (Kakao Kit)
  준비 중입니다. (임시 화면)

카카오톡 키트 1.0.0

  아무 키나 누르면 닫힙니다.
```

4. 키보드의 아무 키나 누르면 창이 닫힙니다.

화면의 `1.0.0` 은 코드 안의 번호이며, 개발이 끝났다는 뜻이 아닙니다. 위처럼 나오지 않으면 [15장](#troubleshooting)을 보세요.

같은 확인을 명령으로 하려면: 탐색기 위쪽 주소 칸을 클릭하고 `cmd` 를 입력한 뒤 Enter를 누르면 그 폴더에서 검은 창이 열립니다. 거기에 `.\kakao.cmd version` 을 입력하고 Enter를 누르면 `카카오톡 키트 1.0.0` 이 나옵니다.

## 6. 실행 방법

### 방법 1. 더블클릭 (가장 쉬움)

`시작.bat` 을 더블클릭합니다. 지금은 임시 화면이 나옵니다. 번호 메뉴는 ⏳ 예정입니다.

### 방법 2. 명령 프롬프트(cmd)

1. 탐색기에서 키트 폴더를 엽니다.
2. 위쪽 주소 칸을 클릭하고 `cmd` 를 입력한 뒤 Enter를 누릅니다.
3. 검은 창에서 `.\kakao.cmd version` 을 입력하고 Enter를 누릅니다.

### 방법 3. PowerShell 또는 Windows Terminal

같은 폴더에서 `.\kakao.cmd version` 을 입력합니다. PowerShell에서는 앞의 `.\` 가 꼭 필요합니다.

### 왜 `kakao` 가 아니라 `.\kakao.cmd` 인가요?

윈도우에는 현재 폴더의 프로그램을 이름만으로 찾지 못하게 하는 보안 설정(환경 변수 `NoDefaultCurrentDirectoryInExePath`)이 있습니다. 이 PC에서는 값이 1로 켜져 있어서 `kakao version` 만 입력하면 "인식할 수 없다"는 오류가 났습니다. PowerShell은 설정과 상관없이 항상 `.\` 를 요구합니다. 그래서 **어느 환경에서나 통하는 `.\kakao.cmd`** 를 쓰는 것이 안전합니다.

### 다른 폴더에서 실행하기

전체 경로를 쓰면 어느 폴더에서든 실행됩니다. 예: `D:\KakaoKit\kakao.cmd version`. 경로에 공백이 있으면 따옴표로 감쌉니다.

### 환경 변수 (설정값)

환경 변수는 윈도우에 저장된 이름표 붙은 설정값입니다. **키트가 직접 읽는 것은 `KAKAO_KIT_HOME` 하나뿐**이며 모두 선택 사항입니다. 비밀번호나 토큰 같은 비밀 값을 환경 변수나 파일로 받는 기능은 없습니다.

| 이름 | 누가 정하나 | 뜻 | 기본값 |
|---|---|---|---|
| `KAKAO_KIT_HOME` | 사용자(선택) | 키트의 데이터 폴더(설정·기록·내보내기)를 이 폴더로 바꿉니다. 원래 자동 시험용입니다. | 없음 → `%LOCALAPPDATA%\KakaoKit` |
| `KAKAO_E2E` | 개발자(선택) | `1` 로 두면 실제 카카오톡을 조작하는 시험을 실행하도록 정해 둔 이름입니다. 시험 도우미 `Test-E2EEnabled`(`tests\_Load.ps1`)가 이 변수를 읽고, 글자가 정확히 `1` 일 때만 켜집니다. 아직 이 도우미를 쓰는 시험은 없고 7단계부터 사용할 예정입니다(⏳). | 없음 → 실행하지 않음 |
| `NoDefaultCurrentDirectoryInExePath` | 윈도우 보안 설정 | `1` 이면 현재 폴더의 프로그램을 이름만으로 찾지 않습니다. 키트가 바꾸지 않으며 바꿀 필요도 없습니다. | PC마다 다름 (이 PC는 1) |
| `LOCALAPPDATA` | 윈도우 | 사용자 데이터 폴더의 기준 위치입니다. | 윈도우가 정함 |

`KAKAO_KIT_HOME` 을 바꾸려면 cmd에서 `set KAKAO_KIT_HOME=D:\KitData`, PowerShell에서 `$env:KAKAO_KIT_HOME = 'D:\KitData'` 를 입력한 뒤 같은 창에서 키트를 실행합니다. 그 창에서만 적용되고 창을 닫으면 사라집니다.

### 실행하면 내부에서 일어나는 일

1. `kakao.cmd` 가 그 창의 글자표를 UTF-8(65001)로 바꿉니다. 한글이 깨지지 않게 하려는 것이며, 그 창에만 적용됩니다.
2. `powershell -NoProfile -ExecutionPolicy Bypass -File src\kakao.ps1 <입력한 내용>` 을 실행합니다. `-NoProfile` 은 개인 설정 파일을 읽지 않는다는 뜻이고, `-ExecutionPolicy Bypass` 는 **이번 실행에만** 스크립트 실행을 허용한다는 뜻입니다. 컴퓨터의 보안 설정은 바꾸지 않습니다.
3. 라우터(`src\kakao.ps1`)가 첫 단어를 보고 명령을 실행하고, 한글 문구를 출력하고, 종료 코드를 돌려줍니다.

### 종료 코드 (결과 번호)

| 번호 | 뜻 | 지금 나오나요? |
|---|---|---|
| 0 | 성공 | ✅ |
| 1 | 사용법 오류 또는 권한 없음 (명령 없음, 모르는 명령, 사람만 할 수 있는 작업 등) | ✅ |
| 2 | 안전장치가 중단함 (창이 다르거나 사람이 키보드·마우스를 만짐 등) | ⏳ 해당 기능이 연결되면 |
| 3 | 환경 문제 (카카오톡이 꺼져 있음, 클립보드 사용 불가, 설정 파일 손상 등) | ⏳ 해당 기능이 연결되면 |
| 4 | 검증되지 않은 카카오톡 버전이라 보내기가 잠김 | ⏳ 해당 기능이 연결되면 |

확인 방법: cmd에서는 `echo %errorlevel%`, PowerShell에서는 `$LASTEXITCODE` 를 입력합니다.

## 7. 사용 방법

### 지금 할 수 있는 일

- 버전 확인: `.\kakao.cmd version` 을 입력하면 `카카오톡 키트 1.0.0` 이 나옵니다(종료 코드 0).
- 임시 안내 화면 보기: `시작.bat` 을 더블클릭합니다.
- 명령 없이 `.\kakao.cmd` 만 입력하면 `명령이 없습니다. 지금 쓸 수 있는 명령: version (버전 보기), status (점검), rooms (허용 방 관리), open (방 열기 확인), read (대화 읽기), search (대화 찾기), send (보내기, 지금은 잠겨 있음), help (도움말). 자세한 설명은 kakao help` 가 나옵니다(종료 코드 1).
- 모르는 명령을 입력하면 `알 수 없는 명령입니다: <입력한 글자>  (지금 쓸 수 있는 명령: version, status, rooms, open, read, search, send, help. 자세한 설명은 kakao help)` 가 나옵니다(종료 코드 1).
- `.\kakao.cmd help` 를 입력하면 아래가 나옵니다(종료 코드 0). 카카오톡·설정 파일·기록을 건드리지 않고 글만 보여 줍니다. 아직 없는 명령은 맨 아래 "준비 중인 기능" 줄에만 나오며, 이 줄은 코드의 명령 목록과 어긋나지 않는지 시험이 확인합니다.

```text
카카오톡 키트 사용법: kakao <명령> [옵션]  (PowerShell 에서는 .\kakao.cmd <명령>)
  version   키트 버전을 보여 줍니다.
  status    키트와 카카오톡의 상태를 읽기만 해서 보여 줍니다.
  rooms     허용한 방을 보고 관리합니다. (추가·삭제·권한 변경은 사람만 할 수 있습니다)
  open      허용한 방을 열어 창 제목을 확인하고 닫습니다. (글을 쓰거나 보내지 않습니다)
  read      보관된 대화 파일을 읽습니다. (카카오톡을 조작하지 않습니다)
  search    보관된 대화 파일에서 낱말을 찾습니다. (카카오톡을 조작하지 않습니다)
  send      메시지 보내기입니다. 지금은 안전을 위해 잠겨 있어 아무것도 보내지 않습니다.
  help      이 설명을 보여 줍니다.
준비 중인 기능(아직 쓸 수 없음): export (대화 저장), update (업데이트), uninstall (제거), menu (메뉴)
```

- `help` 뒤에 다른 글자를 붙이면 `help 는 뒤에 글자를 받지 않습니다. kakao help 만 입력하세요.` 가 나옵니다(종료 코드 1).
- `kakao open` 의 화면 문구입니다. 사용법이 틀리면 `사용법: kakao open --room 방이름 [--human]  (허용 목록에 있는 방을 열어 창 제목을 확인한 뒤 닫습니다)` 가 나옵니다(종료 코드 1). 키트가 방을 열어 창 제목이 같은 것을 확인하고 닫으면 `방을 열고 창 제목이 같은 것을 확인하고 닫았습니다: <방 이름>` 이 나옵니다(종료 코드 0). 이미 열려 있던 방이면 닫지 않고 `이미 열려 있는 방이라 그대로 두었습니다. 창 제목은 같은 것을 확인했습니다: <방 이름>` 이 나옵니다(종료 코드 0). 일반 방이면 열기 전에 `일반 방을 열면 상대에게 읽음 표시가 뜰 수 있습니다: <방 이름>` 을 먼저 알립니다.
- `.\kakao.cmd status` 는 키트 버전, 카카오톡 버전·실행 여부, 보내기 모드, 허용된 방 수를 읽기만 해서 보여 줍니다(종료 코드 0). 로그인 상태·모니터 배율·최근 오류는 ⏳ 10단계입니다.
- `.\kakao.cmd rooms list` 는 허용된 방과 권한을 보여 줍니다. 목록에 넣고 빼고 권한을 바꾸는 `rooms add`·`remove`·`set` 은 **사람만** 합니다(`--human` 을 붙이고 키보드 앞에서 직접 입력). 머리 줄은 `방 이름 | 종류 | 사람 읽기 | AI 읽기 | 사람 보내기 | AI 보내기` 이고 방마다 한 줄씩 나옵니다.
- `.\kakao.cmd read <방> [--since 7d|12h] [--last N]` 과 `.\kakao.cmd search <낱말> [--room <방>]` 은 이미 보관된 내보내기 파일에서만 읽고 찾습니다. AI 가 부르면(`--human` 이 없으면) `aiRead` 가 켜진 방만 됩니다. 대화 본문과 찾은 낱말은 기록(로그)에 남지 않고(방 이름과 개수만), 화면에 내기 전에 터미널 제어 문자를 뺍니다. **아직 `export` 가 없어서 보관된 파일이 없으면 `저장된 내보내기 파일이 아직 없습니다. 먼저 대화를 내보내 주세요. (방: <방 이름>)` 로 멈춥니다(종료 코드 3).**
- `.\kakao.cmd send ...` 는 명령줄만 연결되어 있습니다. 실제 보내기는 안전을 위해 잠겨 있어서 어떤 입력을 줘도(`--dry-run` 포함) `보내기는 아직 열리지 않았습니다. 보낸 글을 확인하는 장치(VerifySent)가 아직 없고 사람이 열기로 정하지 않아 안전을 위해 잠가 두었습니다. 아무것도 보내지 않았습니다.` 가 나오고 종료 코드 3으로 멈추며, 카카오톡에는 아무것도 입력하지 않습니다. 옵션을 잘못 쓰면 사용법이 나옵니다(종료 코드 1).
- 예전에는 안내 문구가 아직 없는 `kakao help` 를 알려 주는 어긋남이 있었고 2026-10-31 에 고쳤습니다. `help` 명령 자체는 아직 없습니다(⏳ 11단계).

### 앞으로 쓰게 될 모습 (⏳ 예정, 설계서 기준)

- 메뉴: `시작.bat` 을 열고 숫자 한 번만 누르면 실행됩니다(Enter 불필요).
- 메뉴에서 보내기: `1` → 방 선택(마지막에 쓴 방이 기본) → 메시지 입력 → `Y`. 입력은 4번 이내입니다.
- 명령줄에서 보내기: 설계서에는 `kakao send <방> "<메시지>" [--dry-run] [--yes]` 형식으로 적혀 있고, 특수문자가 많은 글은 `--file <경로>` 또는 표준입력(`-`)으로 받는 방법이 따로 있습니다.
- AI가 쓸 때: `kakao <명령> --json` 으로 결과를 JSON으로 받습니다.

### 안전하게 쓰는 규칙 (기능이 열리면 적용되는 약속)

1. 시험은 나 혼자만 있는 방에서만 합니다.
2. 작업 중에는 키보드와 마우스를 만지지 않습니다. 만지면 안전장치가 작업을 멈춥니다.
3. 친구가 있는 방은 기본으로 보내기가 잠겨 있고, 사람이 직접 풀어야 합니다.
4. 클립보드에 이미지나 파일을 복사해 둔 상태이면 작업을 멈춥니다(원래대로 되돌릴 수 없기 때문).
5. 한 번에 한 방, 한 메시지만 보냅니다. 전송 간격은 최소 2초, 길이는 최대 1000자입니다.
6. 일반 방을 열면 상대에게 "읽음" 표시가 뜰 수 있습니다. 방을 허용 목록에 넣을 때 한 번 알려 드립니다.
7. 허용 목록 변경과 사용 동의는 사람이 직접 해야 하고, 자동 실행으로는 할 수 없습니다.

| 옵션 | 뜻 | 단계 |

| `--json` | 결과를 컴퓨터가 읽기 쉬운 JSON으로 출력합니다(AI용). | 11 |
| `--dry-run` | 보내기를 미리보기만 하고 실제 입력은 하지 않습니다. | 8 |
| `--yes` | 확인 질문 없이 진행합니다. 자동 실행에서는 필수입니다. | 8 |
| `--file <경로>` 또는 `-` | 메시지 본문을 파일이나 표준입력에서 받습니다(특수문자에 안전한 경로). | 8 |
| `--allow-unverified` | 검증되지 않은 카카오톡 버전에서 사람이 직접 보내기를 허용합니다. | 8, 10 |
| `--since 7d`, `--last N` | 읽을 범위(최근 7일, 최근 N개)를 정합니다. | 9 |

## 9. 작동 방법 (원리)

### 큰 그림 (비유)

카카오톡은 공식 출입문(API)이 없는 집입니다. 그래서 이 키트는 사용자 대신 **키보드 단축키를 눌러 주는 로봇 손**을 둡니다. 다만 로봇 손은 규칙이 엄격한 **문지기(가드)** 가 허락할 때만 움직이고, 문지기가 조금이라도 의심스러우면 아무것도 누르지 않고 멈춥니다.

### 세 가지 방식과 선택

| 방식 | 설명 | 쓰나요? |
|---|---|---|
| A. 화면 자동화 | 키보드·마우스 입력을 대신 보냅니다. | ✅ 보내기와 방 열기에 사용 |
| B. 공식 대화 내보내기 | 카카오톡 자체 기능(`Ctrl+S`)으로 대화를 글자 파일로 저장한 뒤 그 파일을 읽습니다. | ✅ 읽기의 중심 방식 |
| C. 저장소 해독·앱 분석 | 카카오톡 내부 데이터를 풀어 읽는 방식입니다. | ❌ 쓰지 않음 (약관 충돌) |

### 메시지 보내기의 원리 (⏳ 구현은 8단계, 아래 부품은 ✅)

1. 허용 목록 확인: 방 이름이 글자 그대로 일치하는 방만 통과합니다.
2. 방 열기: 목록을 눈대중으로 클릭하지 않고 검색으로만 엽니다. 메인 창이 채팅 목록 화면이 아니거나, 검색이 열린 것이 확인되지 않거나, 연 창의 제목이 방 이름과 다르면 멈춥니다.
3. 문지기 확인: 창의 주인이 카카오톡인지, 창 제목이 방 이름과 정확히 같은지, 맨 앞에 있는지, 사람이 키보드·마우스를 만지지 않았는지, 눌려 있는 키가 없는지(한/영 키는 제외) 확인합니다.
4. 클립보드 저장: 지금 복사해 둔 글(텍스트일 때만)을 안전하게 저장합니다.
5. 보낼 글을 클립보드에 넣고 정말 들어갔는지 확인합니다.
6. `Ctrl+V` 로 붙여넣고 `Enter` 로 보냅니다.
7. 클립보드를 원래대로 되돌리고 되돌려졌는지 확인합니다.
8. 기록(로그)에 시각·명령·방 이름·결과만 남깁니다. 메시지 본문은 남기지 않습니다.

타자를 치는 대신 붙여넣는 이유: 한글·이모지·긴 글도 글자가 빠지거나 바뀌지 않기 때문입니다.

### 대화 읽기의 원리 (⏳ 구현은 9단계, 파서·보관·읽기·검색 부품은 ✅)

1. 방을 열고 `Ctrl+S` 를 누릅니다. 카카오톡의 "다른 이름으로 저장" 창이 뜹니다.
2. 항상 새 파일 이름을 붙여넣고 `Enter` 를 눌러 저장합니다(같은 이름이 있어 덮어쓰기 질문이 뜨는 일을 막기 위해서입니다).
3. 저장된 파일을 읽습니다. 파일의 모양은 첫 줄 `<방 이름> 님과 카카오톡 대화`, 둘째 줄 `저장한 날짜 : YYYY-MM-DD HH:MM:SS`, 날짜 구분선 `--------------- 2026년 10월 21일 수요일 ---------------`, 메시지 `[닉네임] [오전 2:59] 내용` 입니다.
4. 보관: 방마다 최신본(`latest.txt`) 1개와 가장 새 스냅샷 3개만 남기고, 30일이 지난 스냅샷은 지웁니다(✅ 부품, 가짜 파일로 시험됨). 파일의 첫 줄 방 이름이 등록된 방과 다르면 아무것도 저장하지 않고 멈춥니다. 읽기와 검색은 최신본만 보고, AI 는 방마다 AI 읽기가 켜진 곳만 읽을 수 있습니다. 저장 창으로 내보내는 부분과 명령 연결은 ⏳ 입니다.

### 방 열기의 원리 (⏳ 명령 연결은 7단계, 아래 부품은 ✅)

1. 허용 목록에 있는 방인지 먼저 확인합니다. 아니면 창 목록조차 읽지 않고 멈춥니다.
2. 같은 제목의 방 창이 이미 하나 열려 있으면 그 창을 쓰고(키트가 연 것이 아니므로 닫지 않습니다), 둘 이상이면 어느 것인지 알 수 없어 멈춥니다.
3. 카카오톡 메인 창이 정확히 하나인지, 그리고 지금 화면이 채팅 목록인지(또는 이전 작업이 남긴 검색 화면인지)를 창 안의 화면 이름(구조)으로 읽어 확인합니다. 읽기만 하며 화면 배율·창 크기와 무관합니다. 아니면 아무것도 입력하지 않고 멈춥니다. 친구 탭처럼 확인하지 못한 화면에서는 열지 않습니다.
4. 키보드·마우스에서 손이 떨어지기를 기다린 뒤, 이전 작업이 남긴 검색 화면이면 먼저 `Esc` 한 번으로 닫습니다(안 닫히면 멈춤). 그다음 검색 열기(`Ctrl+F`) → 방 이름 붙여넣기(`Ctrl+V`) 순서로 검색합니다. 목록을 눈대중으로 클릭하지 않습니다.
5. 검색이 열린 것이 구조로 읽히는지 확인합니다. 읽히지 않으면 `Enter` 를 누르지 않습니다.
6. 첫 결과를 `Enter` 1번으로 열고(마우스 클릭 없음, 2026-11-15 실제 확인), 새 창이 최대 8초 안에 생기기를 기다립니다. 새 창의 제목이 방 이름과 글자 그대로 같을 때만 성공입니다.
7. 제목이 다르면 그 창을 닫고 멈춥니다. 닫는 것은 키트가 연 창뿐이고, 카카오톡 소유이면서 제목이 정확히 같은 창에만 닫기 요청 하나를 보냅니다. 성공하든 멈추든 마지막에는 메인 창의 검색을 `Esc` 한 번으로 닫아 다음 사용이 막히지 않게 합니다(검색이 열려 있다고 읽힐 때만 보내며, 닫지 못하면 경고만 남깁니다).

방을 열면 상대에게 "읽음" 표시가 뜰 수 있어 되돌릴 수 없으므로, 확인하지 못하면 열지 않는 것이 이 부품의 기본 규칙입니다. 2026-11-15 부터 화면 글자 읽기(OCR)와 고정 픽셀 위치를 쓰지 않습니다. 이전에는 화면 배율·창 크기에 따라 글자 위치가 달라(같은 창이 150%에서는 588x753, 100%에서는 392x502) 기준과 다르면 열지 못하고 멈췄습니다. 지금은 카카오톡 창 안의 화면 이름(채팅 탭은 `ChatRoomListView`, 검색이 열리면 목록 이름이 `SearchListCtrl` 로 바뀜, 친구 탭은 `ContactListView`)을 읽으므로 배율과 창 크기에 상관없습니다. 대신 "검색 결과가 정확히 1건인가" 확인은 없어졌습니다. 비슷한 이름의 다른 방이 첫 결과이면 그 방이 열려 "읽음"이 뜰 수 있고, 그때는 열린 창의 제목이 다르다는 이유로 그 창만 닫고 멈추며 글은 보내지 않습니다. 이 PC의 100% 배율 채팅 탭에서만 확인했고(1회), 다른 배율·탭·일반 방은 확인하지 못했습니다.

### 문지기가 막는 것

- 허용 키 6개(`Ctrl+S`, `Ctrl+V`, `Ctrl+C`, `Ctrl+F`, `Enter`, `Esc`) 외에는 어떤 키도 보내지 않습니다.
- `Esc` 는 메인 창(제목이 정확히 `카카오톡`)에만, 그리고 검색이 열려 있다고 읽힐 때만 보냅니다(2026-11-15 사용자 승인). 카카오톡에서 `Esc` 는 채팅 창을 닫아 버리므로(실제로 겪은 실수입니다) 방 창에는 어떤 경우에도 가지 않도록 코드 양쪽(PowerShell, C#)에서 제목을 확인해 막고, 시험이 이를 강제합니다.
- 창 오른쪽 위 ≡ 메뉴는 클릭하지 않습니다. 그 안에 "대화 내용 모두 삭제"와 "채팅방 나가기"가 바로 옆에 붙어 있습니다.
- "확인"과 "입력"을 한 번의 동작으로 묶어서, 확인한 뒤 입력하기 전 사이에 창이 바뀌는 틈이 없게 했습니다.
- 입력 직전에 눌려 있는 키가 있으면 입력하지 않습니다. 사람이 키를 누른 채 Ctrl 조합이 나가면 엉뚱한 단축키가 되기 때문입니다. **한/영 키만은 예외**입니다. 일부 키보드·입력기에서는 손을 떼도 이 키가 계속 눌린 것으로 읽혀서(이 PC에서 확인), 이것까지 막으면 아무것도 보낼 수 없기 때문입니다. 다른 키는 예외가 없습니다.

### D. 문지기가 입력을 허락하는 순서 (부품 ✅, 가짜 부품으로 시험됨)

```text
  -> 마지막 입력 이후 사람의 입력이 없었는가?
  -> 한 번의 동작으로 [확인 + 입력] 을 함께 실행
  하나라도 틀리면: 입력 0개, 한글 오류 문구, 종료 코드 2
```

### E. 방 열기 (부품 ✅, 실제 카카오톡 시험은 일부만)

```text
Open-KakaoRoom <방 이름>
  1. 허용 목록 확인 ................... 통과 못 하면 아무것도 하지 않음
  2. 같은 제목의 창이 이미 있나? ...... 하나면 재사용(닫지 않음), 둘 이상이면 멈춤
  3. 메인 창 1개 + 지금 화면이 채팅 목록(또는 남은 검색)인가? .. 아니면 입력 없이 멈춤 (구조 이름으로 읽음, 배율 무관)
     남은 검색이 있으면 Esc 1번으로 먼저 닫음 ...... 안 닫히면 멈춤
  4. 손 떼기 확인 -> 검색 열기(Ctrl+F) -> Ctrl+V
  5. 검색이 열렸는가? (구조로 읽음) ........ 아니면 Enter 없이 멈춤
  6. 첫 결과를 Enter 1번으로 엶 (마우스 클릭 없음)
  7. 새 창 제목이 방 이름과 글자 그대로 같은가? (최대 8초 기다림)
       같으면 성공 / 다르면 그 창을 닫고 멈춤 / 시간이 지나면 멈춤
     (성공하든 멈추든 끝에서 메인 창의 검색을 Esc 1번으로 닫음: 검색이 열려 있다고 읽힐 때만)
  8. 끝나면 키트가 연 창만 닫기 (이미 열려 있던 창은 닫지 않음)
```

### 이렇게 만든 이유

- **`.bat` + 윈도우 기본 PowerShell 5.1**: 따로 설치할 것이 없고, 관리자 권한이 없는 PC에서도 그대로 동작합니다. 설치는 폴더 복사, 제거는 폴더 삭제입니다. (Python이나 Node.js 방식도 검토했지만, 별도 설치와 호환 문제 때문에 선택하지 않았습니다.)
- **C# 코드 조각**: 키 입력을 정확하게 보내는 윈도우 기능은 PowerShell 문법만으로는 어려워서, 실행 중에 컴파일하는 C# 조각으로 만들었습니다. 윈도우에 들어 있는 .NET만 씁니다.
- **한글 문구 사전 한 곳**: 영어 문구가 새어 나오는 것을 막고, 시험이 문구를 쉽게 검사할 수 있습니다.
- **가짜 부품(Provider)으로 시험**: 문지기는 실제 윈도우 기능 대신 가짜 부품을 끼워 "입력이 한 번도 전달되지 않았다"는 것을 숫자로 증명합니다.

| 화면 캡처 (방 열기 확인용) | 키트가 카카오톡 창을 읽음 | 메모리에서만 (저장하지 않음) | 아니오 | 다른 방의 이름과 미리보기가 찍힐 수 있어 읽은 글자를 기록하지 않습니다. 개발 중 사람이 확인하려고 찍은 캡처는 건마다 승인을 받고 확인 직후 지웠으며 저장소에 올리지 않았습니다(`.gitignore` 가 그림 파일을 제외). |
| 내보낸 대화 파일 | 카카오톡 공식 기능 | `%LOCALAPPDATA%\KakaoKit\exports\<방 폴더>\` (보관 부품 ✅, 지금은 만들어지지 않음. 카카오톡에서 저장해 오는 부분 ⏳) | 아니오 | 타인의 대화가 들어 있습니다. 방마다 최신본(`latest.txt`) 1개와 스냅샷 3개, 30일 초과 삭제. |

키트는 대화 내용을 인터넷으로 보내지 않습니다. 다만 **읽은 대화를 AI 서비스에 넘기면 그 내용은 컴퓨터 밖으로 나갑니다.** 이를 막기 위해 방마다 "AI 읽기 허용" 스위치를 기본으로 꺼 두었고, 켤 때 이 사실을 알리고 동의를 받을 예정입니다(⏳).

### 12.3 알려진 보안 한계 (숨기지 않고 적습니다)

1. **`kakao.cmd` 의 인자 해석**: 윈도우 cmd가 명령줄을 먼저 해석하기 때문에, 메시지 같은 믿을 수 없는 글을 명령줄 인자에 그대로 이어 붙여 호출하면 `&` 나 `%이름%` 이 명령으로 실행될 수 있습니다. 이는 cmd의 구조라 이스케이프로 완전히 막을 수 없습니다. 그래서 메시지 본문은 `--file` 이나 표준입력으로만 받고, 자동 호출은 `powershell -NoProfile -ExecutionPolicy Bypass -File src\kakao.ps1` 을 직접 부르도록 할 예정입니다(⏳ 8·11단계). 2026-10-31 직접 확인한 범위: `kakao.cmd` 에 `&`·`|` 가 따옴표 없이 그대로 도착하면 그 뒤의 글이 **실제로 명령으로 실행됩니다.** 따옴표로 감싼 경우와 `src\kakao.ps1` 을 직접 부르는 경우(특수문자를 넣어도 실행되지 않음)는 안전하며, 이 두 가지는 시험으로 고정했습니다. 지금은 `version` 하나뿐이고 입력한 글자를 명령 이름 비교에만 써서 사용자가 직접 칠 때의 위험은 낮지만, 메시지 같은 믿을 수 없는 글을 `kakao.cmd` 로 넘기면 안 됩니다.
2. **설정 파일은 일반 글자 파일**입니다. 같은 사용자 계정으로 실행되는 사람이나 프로그램이 직접 고치면 허용 목록을 바꿀 수 있습니다. "사람만 변경" 규칙은 명령 수준에서만 지킵니다. 읽기 전용 설정 등은 12단계에서 검토합니다.
3. **`KAKAO_KIT_HOME` 환경 변수**로 데이터 폴더를 바꿀 수 있습니다(원래 시험용). 실제 사용에서도 적용되므로, 기본 폴더가 아닌 곳을 쓰면 명령마다 표시하도록 할 예정입니다(⏳ 11단계).
4. **키 입력 방식의 실제 동작**: 새로 만든 입력 방식(SendInput)으로 클릭, 붙여넣기(`Ctrl+V`), 더블클릭, 창 닫기는 실제 카카오톡에서 통과했습니다. `Ctrl+S`(저장 창 열림과 저장 완료·파일 읽기를 2026-11-15 에 1회 확인, 반복·다른 환경은 미확인), `Ctrl+A`(금지) 와 다른 키보드·입력기, 사람 손 감지의 오탐(만지지 않았는데 멈춤)은 아직 확인하지 못했습니다(⏳ 7~9단계).
5. **붙여넣기 직후 클립보드 복원 타이밍**: 카카오톡이 붙여넣기를 끝내기 전에 복원하면 원래 클립보드 글이 대신 전송될 위험이 있어, 복원 전에 기다리는 시간을 넣고 실제로 확인할 계획입니다(⏳ 8단계).
6. **클립보드를 잠깐 잠그는 프로그램**: 윈도우 클립보드 기록이나 캡처 도구가 변경 직후 클립보드를 붙잡을 수 있습니다. 키트는 읽기·쓰기 결과를 확인하고 재시도하며, 끝내 안 되면 작업을 멈춥니다.
7. **같은 계정에서 이미 실행 중인 악성 프로그램**은 이 키트가 막을 수 없습니다. 일반적인 한계입니다.
8. **화면 이름(구조)에 기대는 판정**: 방 열기는 카카오톡 26.9.2.5342 의 창 안 화면 이름(`ChatRoomListView`, `SearchListCtrl` 등)을 읽어 화면을 판정합니다. 카카오톡이 바뀌어 이름이 달라지면 확인하지 못해 열지 않고 멈춥니다(안전한 쪽). 이름은 이 PC 의 100% 배율 채팅 탭과 친구 탭에서 읽었고 오픈채팅 탭과 다른 배율에서는 읽어 보지 못했습니다. 일반 방(1:1·단체방)도 확인하지 못했습니다.
9. **방 열기는 되돌릴 수 없는 일입니다**: 방을 열면 상대에게 '읽음' 표시가 뜰 수 있습니다. 그래서 허용한 방, 채팅 목록 화면, 검색 열림, 창 제목 일치를 모두 확인한 뒤에만 열지만, 비슷한 이름의 다른 방이 첫 결과이면 그 방이 먼저 열려 읽음 표시가 뜰 수 있고, 확인이 맞았더라도 이미 일어난 읽음 표시를 되돌릴 방법은 없습니다.
10. **150% 모니터에서 방 열기가 멈추던 결함 (2026-11-11 고침, 2026-11-12 S5 에서 150% 방 열기 1회 통과 확인)**: 2026-11-02 읽기 전용 점검(키·마우스 입력 0, 화면 캡처 0)에서, 카카오톡 메인 창이 150% 모니터에 있을 때 크기는 588x753 인데 윈도우가 알려 주는 창 배율은 100%였습니다(같은 프로그램의 다른 작은 창은 150%로 읽혔습니다). 그래서 고치기 전의 키트는 "기준(392x502)과 크기가 다르다"고 보고 방을 열지 않았습니다. 열지 않는 쪽으로 틀린 것이라 안전하지만, 이때 나오는 안내 문구는 "모니터 배율 100%"라고 말해 오해를 부릅니다. 100% 모니터에서는 이 문제가 없고 실제 열기·닫기를 통과했습니다. 원인(2026-11-10 측정으로 확인): 카카오톡의 메인 창과 방 창은 윈도우의 화면 배율 인식이 "시스템 인식"이라, 창 자신의 배율 값이 150% 모니터에서도 100%(96)로 나옵니다. 화면에는 모니터 배율대로 늘어나 보입니다(392x502 × 1.5 = 588x753). 같은 모니터의 알림 창은 "모니터별 인식"이라 150%(144)로 맞게 읽혔습니다. 고친 방법(2026-11-11): 창 자신의 값 대신 창이 놓인 모니터의 배율을 읽습니다(시험 6개 추가, Ocr 47개 → 53개). 보강(2026-11-11, Codex 검증 지적): 호출한 스레드가 모니터별 DPI 인식일 때만 모니터 값을 믿고, 아니면(DPI 설정이 실패한 경우) 창 값을 써서 고치기 전과 같은 동작으로 돌아갑니다. 이때 항상 안전하게 거절된다는 보장은 없고(화면 좌표가 가상화되는 경우는 확인하지 못했습니다), 새 프로세스가 실제로 모니터별 인식이 되는 것만 시험으로 확인했습니다. 확인한 것: 읽기 전용 점검(입력·화면 캡처 0)에서 메인 창(588x753)의 창 배율 96, 모니터 배율 144, 새 배율 1.5였고 기준 크기와 맞았습니다(고치기 전에는 1.0이라 맞지 않았음). 2026-11-12 S5 에서 150% 모니터의 방 열기·닫기를 1회 통과했습니다(한 번뿐).

## 16. 자주 묻는 질문 (FAQ)

**Q1. 카카오가 만든 공식 프로그램인가요?**

**Q3. 관리자 권한이나 UAC 창이 필요한가요?**

아니요. 어떤 단계에서도 관리자 권한을 요청하지 않습니다.

**Q4. 인터넷이 필요한가요?**

키트는 인터넷을 쓰지 않습니다. README.html 도 글꼴이나 스크립트를 인터넷에서 가져오지 않아 인터넷 없이 열립니다.

**Q5. 제 카카오톡 비밀번호를 저장하나요?**

아니요. 비밀번호를 저장하지도 입력하지도 않습니다. 로그인은 카카오톡 앱에서 직접 하세요.

**Q6. 제 대화 내용이 어딘가로 전송되나요?**

키트는 대화 내용을 외부로 보내지 않습니다. 단, 읽은 대화를 AI 서비스 등에 직접 넘기면 그 내용은 컴퓨터 밖으로 나갑니다. 그 책임은 사용자에게 있습니다.

**Q7. 지금 메시지를 보낼 수 있나요?**

아니요. 보내기는 8단계에서 만들 예정이며, 지금은 `version` 만 됩니다.

**Q8. 맥이나 스마트폰에서도 되나요?**

아니요. 윈도우 PC 전용입니다.

**Q9. 윈도우 화면이 영어인데 괜찮나요?**

괜찮습니다. 개발 PC가 영어 화면이고, 키트의 문구는 언제나 한글입니다. 한글 윈도우나 다른 윈도우 버전은 확인하지 못했습니다.

**Q10. 카카오톡이 업데이트되면 어떻게 되나요?**

26.9.0.5337 만 검증했습니다(이 PC의 카카오톡은 그 뒤 자동 업데이트로 26.9.1.5339 가 되었고, 클릭·붙여넣기·방 열기·창 닫기만 시험했습니다). 앞으로는 다른 버전에서 읽기만 허용하고 보내기를 잠글 예정입니다(⏳ 10단계). 카카오톡 업데이트 자체에는 간섭하지 않습니다.

**Q11. 친구에게 자동으로 메시지를 보내도 되나요?**

기본적으로 막혀 있습니다. 친구가 있는 방은 "미검증 유형"이라 읽기만 되고 보내기는 잠겨 있으며, 사람이 직접 풀어야 하고 AI는 풀 수 없습니다. 시험도 나 혼자만 있는 방에서만 합니다.

**Q12. `Esc` 키는 어떻게 쓰나요?**

카카오톡에서 `Esc` 는 채팅 창을 닫아 버려서 오래 금지했습니다. 2026-11-15 에 사용자가 "메인 창에서 검색을 닫는 용도"로만 허용했고, 대상 창 제목이 정확히 `카카오톡`(메인 창)일 때, 그리고 검색이 열려 있다고 읽힐 때만 보냅니다. 방 창에는 어떤 경우에도 가지 않도록 코드 양쪽(PowerShell, C#)에서 막고 시험이 확인합니다.

**Q13. 왜 글을 치지 않고 붙여넣나요?**

한글·이모지·긴 글도 글자가 빠지거나 바뀌지 않게 하려는 것입니다. 대신 내가 복사해 둔 글을 잠깐 쓰므로, 끝나면 원래대로 되돌립니다. 이미지나 파일이 복사되어 있으면 되돌릴 수 없어서 작업을 멈춥니다.

됩니다. 폴더째 옮기세요. 폴더 이름에 `^` 나 `%` 가 있어도 `시작.bat` 은 동작합니다(2026-10-28 수정). 다만 `%PATH%` 처럼 존재하는 환경 변수 이름을 `%` 로 감싼 폴더 이름은 윈도우가 먼저 바꿔 버려 실행되지 않습니다.

**Q20. 방 열기는 실제 카카오톡으로 시험해 봤나요?**

방 열기는 2026-11-15 부터 화면 글자 읽기를 쓰지 않습니다(부품만 남아 있습니다). 키트는 그러지 않습니다. 카카오톡 창을 메모리에서만 읽고 디스크에 쓰지 않으며, 읽은 글자는 검색 결과 판정에만 쓰고 기록이나 화면에 내보내지 않습니다. 키트 코드에는 인터넷에 접속하는 부분이 없습니다(윈도우 안의 글자 읽기 기능이 내부에서 어떻게 동작하는지는 확인하지 못했습니다). 화면에 다른 방의 이름이 보일 수 있으므로, 개발 중 사람이 확인하려고 찍는 캡처는 건마다 승인을 받고 확인 직후 지웁니다.

**Q22. 모니터가 여러 대이거나 화면 배율이 달라도 되나요?**

100% 모니터에서는 됩니다. 150% 모니터에서는 아직 실제로 열어 본 적이 없습니다. 방 열기는 카카오톡 창이 놓인 모니터의 배율에 맞춰 판정하도록 만들었고, 창 크기가 기준과 다르면 열지 않고 멈춥니다. 150% 모니터에서 창 배율이 100%로 잘못 읽혀 멈추던 결함은 고쳤고(12.3의 10번), 창 배율을 올바르게 읽는 것까지만 확인했습니다. 방을 실제로 여는 시험은 100%에서만 했고, 125%·200% 같은 다른 배율은 가짜 시험 자료로만 확인했습니다. 작업 중에 창을 배율이 다른 모니터로 옮기거나 창 크기를 바꾸면 안전장치가 멈춥니다.

### 설명서 html 만들기

설명서의 원본은 `README.md` 와 `README.en.md` 입니다. html은 아래 도구로 만들며, 손으로 고치지 않습니다.

```text
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Readme.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Readme.ps1 -Check
```

첫 줄은 html 두 개를 다시 만들고, 둘째 줄은 만들지 않고 최신인지만 확인합니다(다르면 종료 코드 1).

### 배포와 저장소 운영 (GitHub)

- 브랜치: 기본 브랜치 `main` 에 직접 올리지 않고, 작업 브랜치에서 풀 리퀘스트(PR)를 거쳐 합칩니다.

### 개발 규칙 (자동 시험이 강제하는 것)

- `.ps1` 은 UTF-8 BOM 포함, `.bat` 과 `.cmd` 는 BOM 없음 + CRLF. 파일을 쓴 뒤 `tools\Write-Bom.ps1 -All` 로 보정합니다.
- `throw` 가 있는 모든 함수의 첫 문장은 `$ErrorActionPreference = 'Stop'` 입니다(호출한 쪽의 오류 설정 때문에 안전장치가 무시되는 것을 막기 위해서입니다).
- 허용 키는 `Ctrl+S`, `Ctrl+V`, `Ctrl+C`, `Ctrl+F`, `Enter`, `Esc` 뿐이며 `Ctrl+A`(카카오톡 메인 창에서는 친구 추가 단축키)는 허용하지 않고, `Esc` 는 메인 창 제목일 때만 허용하고 코드에 나오는 자리가 정해져 있어야 합니다(시험이 강제).
- 실제 카카오톡을 조작하는 시험을 켜는 스위치는 환경 변수 `KAKAO_E2E=1` 이지만, 아직 이 스위치를 쓰는 자동 시험은 없습니다. 지금까지의 실제 시험은 사용자가 시작을 알릴 때마다 따로 실행했고, 시험 방은 본인 혼자 있는 방만 씁니다(7단계부터).
- 정적 분석(PSScriptAnalyzer)은 설치되어 있지 않아 실행하지 못했습니다.
