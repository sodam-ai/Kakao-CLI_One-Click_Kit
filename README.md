## 1. 이 프로젝트는 무엇인가요?

**한 줄 설명:** 윈도우(Windows)용 카카오톡 PC 앱을 명령 한 줄 또는 `시작.bat` 더블클릭으로 다룰 수 있게 만드는 도구 모음입니다.

### 왜 필요한가요?

카카오톡에는 프로그램이 직접 쓸 수 있는 공식 명령 기능(API)이 없습니다. 그래서 이 키트는 사람이 키보드로 하는 동작(붙여넣기 `Ctrl+V`, 전송 `Enter`, 대화 저장 `Ctrl+S`)을 **대신 눌러 주는 방식**으로만 동작합니다. 사용자는 두 부류를 생각하고 만들고 있습니다.

1. 코딩을 모르는 사람: 번호를 누르는 한글 메뉴 화면 (⏳ 예정)
2. AI 도우미(예: Claude Code): `kakao <명령> --json` 형태의 명령줄 (⏳ 예정)

### 만들려는 기능 (목표)

- 내가 허용한 방에만 메시지 보내기
- 대화 읽기: 카카오톡의 공식 "대화 내보내기" 기능을 사용
- 저장해 둔 대화에서 키워드 검색
- 환경 점검, 설치·업데이트·제거
- 오류가 나면 비개발자도 이해할 수 있는 한글 설명과 기록(로그)을 남김
- 제거해도 카카오톡 앱과 대화 데이터는 건드리지 않음

### 하지 않는 것 (비목표)

- 카카오톡 대화 저장소(DB)를 해독하거나 앱을 분석·변조하는 방식: 이용약관과 충돌할 수 있어 쓰지 않기로 확정했습니다.
- 실시간 감시, 자동 답장 봇, 여러 방에 한꺼번에 보내기
- 사진·파일 같은 글자가 아닌 메시지의 읽기·보내기
- 카카오톡 외의 메신저, macOS(맥), 스마트폰

### 참고한 것

macOS 전용 오픈소스 도구(이름: kakaocli)가 있지만 맥에서만 동작해서 윈도우에서는 쓸 수 없었습니다. 그래서 같은 목적을 **윈도우용으로 처음부터 새로 만들었고, 그 도구의 코드를 가져다 쓰지 않았습니다.**

### 사용자가 정한 4가지 약속

| 약속 | 지금 상태 |
|---|---|
| 관리자 권한(UAC) 창이 절대 뜨지 않는다 | ✅ 관리자 권한을 요청하는 코드가 없습니다. 레지스트리·서비스·작업 스케줄러 등록, Program Files 쓰기도 없습니다(자동 시험이 검사). |
| 영어 메뉴는 한글로 쓰거나 한글과 영어를 함께 쓴다 | ✅ 모든 안내 문구를 한글 문구 사전 한 곳에서 만듭니다. 윈도우의 영어 `pause` 문구도 한글로 바꿨습니다. 메뉴 화면 자체는 ⏳ 예정입니다. |
| 메뉴에 들어가는 단계를 최소로 한다 | ⏳ 설계됨: 숫자 한 번만 누르면 실행, 보내기는 입력 4번 이내. 메뉴는 아직 없습니다. |
| 메뉴는 간단하면서 자세하게 | ⏳ 설계됨. 메뉴는 아직 없습니다. |

## 2. 현재 상태: 되는 것과 아직 안 되는 것

개발은 13단계로 나뉘어 있고 지금까지 1~6단계를 끝냈습니다. 표의 "부품 완료"는 **그 기능의 부품(함수)이 만들어졌고 자동 시험을 통과했지만, 사용자가 부를 수 있는 명령으로는 아직 연결되지 않았다**는 뜻입니다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 시작 틀: 한글 깨짐 방지, 관리자 권한 없음, `시작.bat` 임시 화면, `kakao version` | ✅ 완료 |
| 2 | 설정·허용 방 목록·사용 동의 | ✅ 부품 완료 |
| 3 | 기록(로그)과 오류 보고서 | ✅ 부품 완료 |
| 4 | 키 입력 계층과 안전장치("문지기") | ✅ 부품 완료 (실제 카카오톡에 입력하는 시험은 ⏳) |
| 5 | 클립보드 보존과 복원 | ✅ 부품 완료 |
| 6 | 내보내기 파일 읽기(파서) | ✅ 부품 완료 |
| 7 | 방 열기 | ⏳ 부품 완료(가짜 부품으로 시험), 실제 화면 시험과 명령 연결은 아직. 사전 조사에서 키트 코드로 검색 붙여넣기·방 열기·열린 창 제목 확인·창 닫기가 각 1회 통과함 |
| 8 | 메시지 보내기 | ⏳ 예정 |
| 9 | 내보내기·읽기·검색 | ⏳ 예정 |
| 10 | 상태 점검, 카카오톡 버전 확인, 로그인 안내, 미검증 버전 잠금 | ⏳ 예정 |
| 11 | 명령 분배기 완성, 번호 메뉴, `help` | ⏳ 예정 |
| 12 | 첫 실행 동의, 업데이트, 제거 | ⏳ 예정 |
| 13 | 처음부터 끝까지 인수 시험, 사용 설명서 최종본 | ⏳ 예정 |

### 아직 확인하지 못한 것 (솔직한 목록)

- 키트 코드로 실제 카카오톡에 키를 보내는 시험: 7단계에서 합니다. 지금까지 키트 코드로 보낸 입력은 **7단계 사전 조사의 클릭, 붙여넣기(Ctrl+V), 더블클릭(방 열기), 창 닫기 요청뿐**입니다(메시지는 보내지 않았고, 안전장치가 멈추지 않았습니다. 14장 참고). Enter 와 Ctrl+S 등 다른 키, 메시지 보내기·내보내기는 키트 코드로 시험한 적이 없습니다. (개발 전 조사 단계에서 임시 실험으로 보내기·방 열기·내보내기가 되는 것은 확인했습니다.)
- 한글·여러 줄·긴 메시지·이모지의 실제 전송
- 일반 방(1:1, 단체방)에서의 검색·열기·내보내기 (시험용 방은 오픈채팅 방이라, 창 제목과 검색 결과가 일반 방과 다를 수 있습니다)
- 카카오톡이 꺼져 있거나 로그인 화면일 때의 동작
- 같은 이름의 방이 여러 개일 때 구분하는 방법
- 사람 손 감지(키보드·마우스를 만졌는지)의 오탐, 눌린 키 검사가 지나치지 않은지, 화면 배율이 다른 모니터가 섞였을 때의 동작: 한/영 키는 이 PC에서 손을 떼도 계속 눌린 것으로 읽혀 눌린 키 검사에서 뺐습니다(다른 키는 그대로 검사). 다른 키보드·입력기에서도 이 키만 문제인지는 확인하지 못했습니다.
- 시스템 메시지("○○님이 들어왔습니다")가 내보내기 파일에 어떻게 나오는지: 지금은 앞 메시지의 이어지는 줄로 읽힐 수 있습니다.
- 정적 분석 도구(PSScriptAnalyzer): 설치되어 있지 않아 실행하지 못했습니다.
- 백신·SmartScreen의 반응
- 카카오 운영정책의 자동화 관련 조항(원문은 확인하지 못했고, 카카오 개발자 포럼에 화면 자동 조작을 금지한다는 답변이 있었음: 17.2 참고)

## 4. 다운로드와 설치 방법

### 다운로드 방법

**소스는 GitHub의 비공개(private) 저장소 `Kakao-CLI_One-Click_Kit` 에 있습니다.** 아직 공개 저장소가 아니라서 접근 권한이 있는 사람만 받을 수 있고, 누구나 내려받는 공개 주소는 없습니다. 접근 권한이 있다면 둘 중 한 가지로 받습니다.

- 방법 가: GitHub 저장소 페이지의 초록색 `Code` 버튼을 누르고 `Download ZIP` 을 눌러 압축 파일을 받습니다(영어 화면 기준).
- 방법 나: GitHub CLI(`gh`)가 설치되어 있다면 `gh repo clone <소유자>/Kakao-CLI_One-Click_Kit` 을 실행합니다. `<소유자>` 는 저장소를 만든 GitHub 계정 이름입니다.

USB나 압축 파일로 폴더를 직접 받았다면 바로 아래 순서로 설치합니다.

### 설치 방법 (폴더 복사)

1. 압축 파일(.zip)이면 **먼저 완전히 풀어 주세요.** 파일을 우클릭해서 "모두 압축 풀기"(영어 윈도우: Extract All)를 고릅니다. 압축 파일 안에서 바로 실행하면 일부 파일만 임시로 풀려 실패합니다.
2. 풀어 둔 폴더를 원하는 곳에 둡니다. 예: `D:\KakaoKit`. 짧은 영문·숫자 이름을 권장합니다. 폴더 이름에 `%PATH%` 처럼 `%이름%` 꼴은 넣지 마세요(15장의 알려진 한계).
3. 폴더 안에 `시작.bat`, `kakao.cmd`, `src` 폴더가 보이면 준비가 끝난 것입니다.
4. 설치 프로그램도, 회원가입도, 로그인도 없습니다.

### 업데이트 방법

지금은 업데이트 명령이 없습니다(`update` 는 ⏳ 예정). 새 폴더를 받았다면 기존 폴더를 새 폴더로 바꿔 쓰면 됩니다. 저장소를 `gh repo clone` 으로 받았다면 그 폴더 안에서 `git pull` 을 실행해 최신으로 맞출 수도 있습니다. 설정과 기록을 저장하는 기능이 연결된 뒤에는 그것들이 사용자 폴더의 `%LOCALAPPDATA%\KakaoKit` 에 따로 있어서, 프로그램 폴더를 바꿔도 보존됩니다(⏳).

### 제거 방법

**폴더를 삭제하면 끝입니다.** 지금 버전은 폴더 밖에 아무것도 만들지 않습니다. 레지스트리, 바탕화면 바로가기, 시작 메뉴, PATH, 작업 스케줄러 모두 건드리지 않습니다(코드 검색으로 확인했고, 이 PC에 `%LOCALAPPDATA%\KakaoKit` 폴더가 없는 것도 확인했습니다). 앞으로 설정을 저장하는 기능이 연결되면 그 폴더가 생길 수 있고, `uninstall` 명령이 안내합니다(⏳). 어떤 경우에도 카카오톡 앱과 대화 내용은 건드리지 않습니다.

## 5. 빠른 시작 (5분)

지금 할 수 있는 전부입니다. 키트가 제대로 놓였는지 확인합니다.

1. 탐색기에서 키트 폴더를 엽니다.
2. `시작.bat` 을 더블클릭합니다.
3. 검은 창에 아래와 같은 글자가 나오면 **정상**입니다. (앞뒤의 빈 줄은 생략했습니다.)

```text
  카카오톡 키트 (Kakao Kit)
  준비 중입니다. (임시 화면)

카카오톡 키트 1.0.0

  아무 키나 누르면 닫힙니다.
```

4. 키보드의 아무 키나 누르면 창이 닫힙니다.

화면의 `1.0.0` 은 코드 안의 번호이며, 개발이 끝났다는 뜻이 아닙니다. 위처럼 나오지 않으면 [15장](#troubleshooting)을 보세요.

같은 확인을 명령으로 하려면: 탐색기 위쪽 주소 칸을 클릭하고 `cmd` 를 입력한 뒤 Enter를 누르면 그 폴더에서 검은 창이 열립니다. 거기에 `.\kakao.cmd version` 을 입력하고 Enter를 누르면 `카카오톡 키트 1.0.0` 이 나옵니다.

<a id="run"></a>
## 6. 실행 방법

### 방법 1. 더블클릭 (가장 쉬움)

`시작.bat` 을 더블클릭합니다. 지금은 임시 화면이 나옵니다. 번호 메뉴는 ⏳ 예정입니다.

### 방법 2. 명령 프롬프트(cmd)

1. 탐색기에서 키트 폴더를 엽니다.
2. 위쪽 주소 칸을 클릭하고 `cmd` 를 입력한 뒤 Enter를 누릅니다.
3. 검은 창에서 `.\kakao.cmd version` 을 입력하고 Enter를 누릅니다.

### 방법 3. PowerShell 또는 Windows Terminal

같은 폴더에서 `.\kakao.cmd version` 을 입력합니다. PowerShell에서는 앞의 `.\` 가 꼭 필요합니다.

### 왜 `kakao` 가 아니라 `.\kakao.cmd` 인가요?

윈도우에는 현재 폴더의 프로그램을 이름만으로 찾지 못하게 하는 보안 설정(환경 변수 `NoDefaultCurrentDirectoryInExePath`)이 있습니다. 이 PC에서는 값이 1로 켜져 있어서 `kakao version` 만 입력하면 "인식할 수 없다"는 오류가 났습니다. PowerShell은 설정과 상관없이 항상 `.\` 를 요구합니다. 그래서 **어느 환경에서나 통하는 `.\kakao.cmd`** 를 쓰는 것이 안전합니다.

### 다른 폴더에서 실행하기

전체 경로를 쓰면 어느 폴더에서든 실행됩니다. 예: `D:\KakaoKit\kakao.cmd version`. 경로에 공백이 있으면 따옴표로 감쌉니다.

### 환경 변수 (설정값)

환경 변수는 윈도우에 저장된 이름표 붙은 설정값입니다. **키트가 직접 읽는 것은 `KAKAO_KIT_HOME` 하나뿐**이며 모두 선택 사항입니다. 비밀번호나 토큰 같은 비밀 값을 환경 변수나 파일로 받는 기능은 없습니다.

| 이름 | 누가 정하나 | 뜻 | 기본값 |
|---|---|---|---|
| `KAKAO_KIT_HOME` | 사용자(선택) | 키트의 데이터 폴더(설정·기록·내보내기)를 이 폴더로 바꿉니다. 원래 자동 시험용입니다. | 없음 → `%LOCALAPPDATA%\KakaoKit` |
| `KAKAO_E2E` | 개발자(선택) | `1` 로 두면 실제 카카오톡을 조작하는 시험을 실행하도록 정해 둔 이름입니다. 시험 도우미 `Test-E2EEnabled`(`tests\_Load.ps1`)가 이 변수를 읽고, 글자가 정확히 `1` 일 때만 켜집니다. 아직 이 도우미를 쓰는 시험은 없고 7단계부터 사용할 예정입니다(⏳). | 없음 → 실행하지 않음 |
| `NoDefaultCurrentDirectoryInExePath` | 윈도우 보안 설정 | `1` 이면 현재 폴더의 프로그램을 이름만으로 찾지 않습니다. 키트가 바꾸지 않으며 바꿀 필요도 없습니다. | PC마다 다름 (이 PC는 1) |
| `LOCALAPPDATA` | 윈도우 | 사용자 데이터 폴더의 기준 위치입니다. | 윈도우가 정함 |

`KAKAO_KIT_HOME` 을 바꾸려면 cmd에서 `set KAKAO_KIT_HOME=D:\KitData`, PowerShell에서 `$env:KAKAO_KIT_HOME = 'D:\KitData'` 를 입력한 뒤 같은 창에서 키트를 실행합니다. 그 창에서만 적용되고 창을 닫으면 사라집니다.

### 실행하면 내부에서 일어나는 일

1. `kakao.cmd` 가 그 창의 글자표를 UTF-8(65001)로 바꿉니다. 한글이 깨지지 않게 하려는 것이며, 그 창에만 적용됩니다.
2. `powershell -NoProfile -ExecutionPolicy Bypass -File src\kakao.ps1 <입력한 내용>` 을 실행합니다. `-NoProfile` 은 개인 설정 파일을 읽지 않는다는 뜻이고, `-ExecutionPolicy Bypass` 는 **이번 실행에만** 스크립트 실행을 허용한다는 뜻입니다. 컴퓨터의 보안 설정은 바꾸지 않습니다.
3. 라우터(`src\kakao.ps1`)가 첫 단어를 보고 명령을 실행하고, 한글 문구를 출력하고, 종료 코드를 돌려줍니다.

### 종료 코드 (결과 번호)

| 번호 | 뜻 | 지금 나오나요? |
|---|---|---|
| 0 | 성공 | ✅ |
| 1 | 사용법 오류 또는 권한 없음 (명령 없음, 모르는 명령, 사람만 할 수 있는 작업 등) | ✅ |
| 2 | 안전장치가 중단함 (창이 다르거나 사람이 키보드·마우스를 만짐 등) | ⏳ 해당 기능이 연결되면 |
| 3 | 환경 문제 (카카오톡이 꺼져 있음, 클립보드 사용 불가, 설정 파일 손상 등) | ⏳ 해당 기능이 연결되면 |
| 4 | 검증되지 않은 카카오톡 버전이라 보내기가 잠김 | ⏳ 해당 기능이 연결되면 |

확인 방법: cmd에서는 `echo %errorlevel%`, PowerShell에서는 `$LASTEXITCODE` 를 입력합니다.

## 7. 사용 방법

### 지금 할 수 있는 일

- 버전 확인: `.\kakao.cmd version` 을 입력하면 `카카오톡 키트 1.0.0` 이 나옵니다(종료 코드 0).
- 임시 안내 화면 보기: `시작.bat` 을 더블클릭합니다.
- 명령 없이 `.\kakao.cmd` 만 입력하면 `명령이 없습니다. 도움말은 "kakao help" 로 볼 수 있습니다.` 가 나옵니다(종료 코드 1).
- 모르는 명령을 입력하면 `알 수 없는 명령입니다: <입력한 글자>  (도움말: kakao help)` 가 나옵니다(종료 코드 1).
- 알려진 어긋남: 위 안내 문구는 `kakao help` 를 알려 주지만 `help` 는 아직 없습니다(⏳ 11단계). 문구도 `.\kakao.cmd help` 로 고칠 예정입니다.

### 앞으로 쓰게 될 모습 (⏳ 예정, 설계서 기준)

- 메뉴: `시작.bat` 을 열고 숫자 한 번만 누르면 실행됩니다(Enter 불필요).
- 메뉴에서 보내기: `1` → 방 선택(마지막에 쓴 방이 기본) → 메시지 입력 → `Y`. 입력은 4번 이내입니다.
- 명령줄에서 보내기: 설계서에는 `kakao send <방> "<메시지>" [--dry-run] [--yes]` 형식으로 적혀 있고, 특수문자가 많은 글은 `--file <경로>` 또는 표준입력(`-`)으로 받는 방법이 따로 있습니다.
- AI가 쓸 때: `kakao <명령> --json` 으로 결과를 JSON으로 받습니다.

### 안전하게 쓰는 규칙 (기능이 열리면 적용되는 약속)

1. 시험은 나 혼자만 있는 방에서만 합니다.
2. 작업 중에는 키보드와 마우스를 만지지 않습니다. 만지면 안전장치가 작업을 멈춥니다.
3. 친구가 있는 방은 기본으로 보내기가 잠겨 있고, 사람이 직접 풀어야 합니다.
4. 클립보드에 이미지나 파일을 복사해 둔 상태이면 작업을 멈춥니다(원래대로 되돌릴 수 없기 때문).
5. 한 번에 한 방, 한 메시지만 보냅니다. 전송 간격은 최소 2초, 길이는 최대 1000자입니다.
6. 일반 방을 열면 상대에게 "읽음" 표시가 뜰 수 있습니다. 방을 허용 목록에 넣을 때 한 번 알려 드립니다.
7. 허용 목록 변경과 사용 동의는 사람이 직접 해야 하고, 자동 실행으로는 할 수 없습니다.

<a id="how"></a>
## 9. 작동 방법 (원리)

### 큰 그림 (비유)

카카오톡은 공식 출입문(API)이 없는 집입니다. 그래서 이 키트는 사용자 대신 **키보드 단축키를 눌러 주는 로봇 손**을 둡니다. 다만 로봇 손은 규칙이 엄격한 **문지기(가드)** 가 허락할 때만 움직이고, 문지기가 조금이라도 의심스러우면 아무것도 누르지 않고 멈춥니다.

### 세 가지 방식과 선택

| 방식 | 설명 | 쓰나요? |
|---|---|---|
| A. 화면 자동화 | 키보드·마우스 입력을 대신 보냅니다. | ✅ 보내기와 방 열기에 사용 |
| B. 공식 대화 내보내기 | 카카오톡 자체 기능(`Ctrl+S`)으로 대화를 글자 파일로 저장한 뒤 그 파일을 읽습니다. | ✅ 읽기의 중심 방식 |
| C. 저장소 해독·앱 분석 | 카카오톡 내부 데이터를 풀어 읽는 방식입니다. | ❌ 쓰지 않음 (약관 충돌) |

### 메시지 보내기의 원리 (⏳ 구현은 8단계, 아래 부품은 ✅)

1. 허용 목록 확인: 방 이름이 글자 그대로 일치하는 방만 통과합니다.
2. 방 열기: 목록을 눈대중으로 클릭하지 않고 검색으로만 엽니다. 검색 결과가 정확히 1건이 아니면 멈춥니다.
3. 문지기 확인: 창의 주인이 카카오톡인지, 창 제목이 방 이름과 정확히 같은지, 맨 앞에 있는지, 사람이 키보드·마우스를 만지지 않았는지, 눌려 있는 키가 없는지(한/영 키는 제외) 확인합니다.
4. 클립보드 저장: 지금 복사해 둔 글(텍스트일 때만)을 안전하게 저장합니다.
5. 보낼 글을 클립보드에 넣고 정말 들어갔는지 확인합니다.
6. `Ctrl+V` 로 붙여넣고 `Enter` 로 보냅니다.
7. 클립보드를 원래대로 되돌리고 되돌려졌는지 확인합니다.
8. 기록(로그)에 시각·명령·방 이름·결과만 남깁니다. 메시지 본문은 남기지 않습니다.

타자를 치는 대신 붙여넣는 이유: 한글·이모지·긴 글도 글자가 빠지거나 바뀌지 않기 때문입니다.

### 대화 읽기의 원리 (⏳ 구현은 9단계, 파서는 ✅)

1. 방을 열고 `Ctrl+S` 를 누릅니다. 카카오톡의 "다른 이름으로 저장" 창이 뜹니다.
2. 항상 새 파일 이름을 붙여넣고 `Enter` 를 눌러 저장합니다(같은 이름이 있어 덮어쓰기 질문이 뜨는 일을 막기 위해서입니다).
3. 저장된 파일을 읽습니다. 파일의 모양은 첫 줄 `<방 이름> 님과 카카오톡 대화`, 둘째 줄 `저장한 날짜 : YYYY-MM-DD HH:MM:SS`, 날짜 구분선 `--------------- 2026년 10월 21일 수요일 ---------------`, 메시지 `[닉네임] [오전 2:59] 내용` 입니다.
4. 보관: 방마다 최신본 1개와 이전 스냅샷 3개만 남기고, 30일이 지난 스냅샷은 지웁니다(⏳).

### 문지기가 막는 것

- 허용 키 5개(`Ctrl+S`, `Ctrl+V`, `Ctrl+A`, `Ctrl+C`, `Enter`) 외에는 어떤 키도 보내지 않습니다.
- `Esc` 는 절대 보내지 않습니다. 카카오톡에서 `Esc` 는 채팅 창을 닫아 버립니다(실제로 겪은 실수입니다).
- 창 오른쪽 위 ≡ 메뉴는 클릭하지 않습니다. 그 안에 "대화 내용 모두 삭제"와 "채팅방 나가기"가 바로 옆에 붙어 있습니다.
- "확인"과 "입력"을 한 번의 동작으로 묶어서, 확인한 뒤 입력하기 전 사이에 창이 바뀌는 틈이 없게 했습니다.
- 입력 직전에 눌려 있는 키가 있으면 입력하지 않습니다. 사람이 키를 누른 채 Ctrl 조합이 나가면 엉뚱한 단축키가 되기 때문입니다. **한/영 키만은 예외**입니다. 일부 키보드·입력기에서는 손을 떼도 이 키가 계속 눌린 것으로 읽혀서(이 PC에서 확인), 이것까지 막으면 아무것도 보낼 수 없기 때문입니다. 다른 키는 예외가 없습니다.

```text

 AI ------- kakao.cmd (명령줄)  --------+

                                        |
      +----------+----------+-----------+----------+-----------+
      v          v          v           v          v           v
   Config      Log      Guard+Win32    Clip      Parse      (⏳ Room, Send,

      \________ Messages.ko (모든 한글 문구) · Paths · Errors ________/
```

|---|---|---|
| `Messages.ko.ps1` | 사용자에게 보이는 모든 한글 문구를 한 곳에서 만듭니다. | ✅ |
| `Paths.ps1` | 키트 버전, 관리자 권한 여부, 데이터 폴더 위치(`%LOCALAPPDATA%\KakaoKit`)를 계산합니다. 폴더를 만들지는 않습니다. | ✅ |
| `Errors.ps1` | 키트 전용 오류 종류와 종료 코드(1~4)를 정합니다. | ✅ |

| `Log.ps1` | 본문 없는 한 줄 기록, 기록 파일 정리, 오류 보고서 글을 만듭니다. | ✅ 부품 |
| `Win32.ps1` | 윈도우 기능(창 찾기, 키 입력 보내기)을 C# 코드로 불러옵니다. 처음 불러올 때 컴파일하며 약 0.2~0.3초 걸립니다. | ✅ 부품 |
| `Guard.ps1` | 입력 직전 확인(문지기), 허용 키 표, 사람 손 감지, 동시 실행 잠금을 담당합니다. | ✅ 부품 |
| `Clip.ps1` | 클립보드의 글만 저장·교체·복원하고 확인합니다. | ✅ 부품 |
| `Parse.ps1` | 내보내기 글자 파일을 방 이름·저장 시각·메시지 목록으로 바꿉니다. | ✅ 부품 |
| `Ocr.ps1` | 화면 글자 읽기(OCR)로 검색 결과가 방 이름 하나뿐인지 판정합니다. 화면은 메모리에서만 읽고 디스크에 쓰지 않으며 입력을 보내지 않습니다. | ✅ 부품 (실제 화면 시험은 ⏳) |
| `Room.ps1` | 허용된 방만 검색으로 열고, 열기 전에 결과가 정확히 1건인지 확인하며, 연 창의 제목이 방 이름과 글자 그대로 같을 때만 성공으로 봅니다. 확인하지 못하면 열지 않습니다. | ✅ 부품 (명령 연결은 ⏳ 7단계) |

| `Install.ps1` | 첫 실행, 업데이트, 제거 | ⏳ 12단계 |

### 이렇게 만든 이유

- **`.bat` + 윈도우 기본 PowerShell 5.1**: 따로 설치할 것이 없고, 관리자 권한이 없는 PC에서도 그대로 동작합니다. 설치는 폴더 복사, 제거는 폴더 삭제입니다. (Python이나 Node.js 방식도 검토했지만, 별도 설치와 호환 문제 때문에 선택하지 않았습니다.)
- **C# 코드 조각**: 키 입력을 정확하게 보내는 윈도우 기능은 PowerShell 문법만으로는 어려워서, 실행 중에 컴파일하는 C# 조각으로 만들었습니다. 윈도우에 들어 있는 .NET만 씁니다.
- **한글 문구 사전 한 곳**: 영어 문구가 새어 나오는 것을 막고, 시험이 문구를 쉽게 검사할 수 있습니다.
- **가짜 부품(Provider)으로 시험**: 문지기는 실제 윈도우 기능 대신 가짜 부품을 끼워 "입력이 한 번도 전달되지 않았다"는 것을 숫자로 증명합니다.

| 데이터 | 어디서 생기나 | 어디에 저장되나 | 밖으로 나가나 | 비고 |
|---|---|---|---|---|

키트는 대화 내용을 인터넷으로 보내지 않습니다. 다만 **읽은 대화를 AI 서비스에 넘기면 그 내용은 컴퓨터 밖으로 나갑니다.** 이를 막기 위해 방마다 "AI 읽기 허용" 스위치를 기본으로 꺼 두었고, 켤 때 이 사실을 알리고 동의를 받을 예정입니다(⏳).

### 12.3 알려진 보안 한계 (숨기지 않고 적습니다)

1. **`kakao.cmd` 의 인자 해석**: 윈도우 cmd가 명령줄을 먼저 해석하기 때문에, 메시지 같은 믿을 수 없는 글을 명령줄 인자에 그대로 이어 붙여 호출하면 `&` 나 `%이름%` 이 명령으로 실행될 수 있습니다. 이는 cmd의 구조라 이스케이프로 완전히 막을 수 없습니다. 그래서 메시지 본문은 `--file` 이나 표준입력으로만 받고, 자동 호출은 `powershell -NoProfile -ExecutionPolicy Bypass -File src\kakao.ps1` 을 직접 부르도록 할 예정입니다(⏳ 8·11단계). 지금 버전은 입력한 글자를 명령 이름 비교에만 쓰고 실행하지 않아 영향이 없습니다(특수문자 20종으로 시험).
2. **설정 파일은 일반 글자 파일**입니다. 같은 사용자 계정으로 실행되는 사람이나 프로그램이 직접 고치면 허용 목록을 바꿀 수 있습니다. "사람만 변경" 규칙은 명령 수준에서만 지킵니다. 읽기 전용 설정 등은 12단계에서 검토합니다.
3. **`KAKAO_KIT_HOME` 환경 변수**로 데이터 폴더를 바꿀 수 있습니다(원래 시험용). 실제 사용에서도 적용되므로, 기본 폴더가 아닌 곳을 쓰면 명령마다 표시하도록 할 예정입니다(⏳ 11단계).
4. **키 입력 방식의 실제 동작**: 새로 만든 입력 방식(SendInput)이 실제 카카오톡에서 잘 먹는지, 사람 손 감지의 오탐이 어떤지는 아직 실제로 확인하지 못했습니다(⏳ 7·8단계).
5. **붙여넣기 직후 클립보드 복원 타이밍**: 카카오톡이 붙여넣기를 끝내기 전에 복원하면 원래 클립보드 글이 대신 전송될 위험이 있어, 복원 전에 기다리는 시간을 넣고 실제로 확인할 계획입니다(⏳ 8단계).
6. **클립보드를 잠깐 잠그는 프로그램**: 윈도우 클립보드 기록이나 캡처 도구가 변경 직후 클립보드를 붙잡을 수 있습니다. 키트는 읽기·쓰기 결과를 확인하고 재시도하며, 끝내 안 되면 작업을 멈춥니다.
7. **같은 계정에서 이미 실행 중인 악성 프로그램**은 이 키트가 막을 수 없습니다. 일반적인 한계입니다.

## 16. 자주 묻는 질문 (FAQ)

**Q1. 카카오가 만든 공식 프로그램인가요?**

아니요. 카카오와 아무 관계가 없는 비공식 도구입니다. 자세한 내용은 [17장](#legal)을 보세요.

**Q2. 쓰면 카카오톡 계정이 정지되나요?**

알 수 없습니다. 카카오의 별도 운영정책에 자동화 관련 조항이 있는지 확인하지 못했고, 계정 이용 제한이 될 가능성이 있습니다. 그래서 일괄·반복 전송을 만들지 않고, 전송 간격을 2초 이상으로 두고, 시험은 나 혼자만 있는 방에서만 합니다. 이것은 위험을 줄일 뿐 없애지는 못합니다.

**Q3. 관리자 권한이나 UAC 창이 필요한가요?**

아니요. 어떤 단계에서도 관리자 권한을 요청하지 않습니다.

**Q4. 인터넷이 필요한가요?**

키트는 인터넷을 쓰지 않습니다. README.html 도 글꼴이나 스크립트를 인터넷에서 가져오지 않아 인터넷 없이 열립니다.

**Q5. 제 카카오톡 비밀번호를 저장하나요?**

아니요. 비밀번호를 저장하지도 입력하지도 않습니다. 로그인은 카카오톡 앱에서 직접 하세요.

**Q6. 제 대화 내용이 어딘가로 전송되나요?**

키트는 대화 내용을 외부로 보내지 않습니다. 단, 읽은 대화를 AI 서비스 등에 직접 넘기면 그 내용은 컴퓨터 밖으로 나갑니다. 그 책임은 사용자에게 있습니다.

**Q7. 지금 메시지를 보낼 수 있나요?**

아니요. 보내기는 8단계에서 만들 예정이며, 지금은 `version` 만 됩니다.

**Q8. 맥이나 스마트폰에서도 되나요?**

아니요. 윈도우 PC 전용입니다.

**Q9. 윈도우 화면이 영어인데 괜찮나요?**

괜찮습니다. 개발 PC가 영어 화면이고, 키트의 문구는 언제나 한글입니다. 한글 윈도우나 다른 윈도우 버전은 확인하지 못했습니다.

**Q10. 카카오톡이 업데이트되면 어떻게 되나요?**

26.9.0.5337 만 검증했습니다(이 PC의 카카오톡은 그 뒤 자동 업데이트로 26.9.1.5339 가 되었고, 클릭·붙여넣기·방 열기·창 닫기만 시험했습니다). 앞으로는 다른 버전에서 읽기만 허용하고 보내기를 잠글 예정입니다(⏳ 10단계). 카카오톡 업데이트 자체에는 간섭하지 않습니다.

**Q11. 친구에게 자동으로 메시지를 보내도 되나요?**

기본적으로 막혀 있습니다. 친구가 있는 방은 "미검증 유형"이라 읽기만 되고 보내기는 잠겨 있으며, 사람이 직접 풀어야 하고 AI는 풀 수 없습니다. 시험도 나 혼자만 있는 방에서만 합니다.

**Q12. 왜 `Esc` 키를 쓰지 않나요?**

카카오톡에서 `Esc` 는 채팅 창을 닫아 버립니다. 개발 중에 실제로 겪은 실수라서 어떤 경우에도 보내지 않도록 막았습니다.

**Q13. 왜 글을 치지 않고 붙여넣나요?**

한글·이모지·긴 글도 글자가 빠지거나 바뀌지 않게 하려는 것입니다. 대신 내가 복사해 둔 글을 잠깐 쓰므로, 끝나면 원래대로 되돌립니다. 이미지나 파일이 복사되어 있으면 되돌릴 수 없어서 작업을 멈춥니다.

**Q14. `시작.bat` 이 바로 닫혀요.**

[15장](#troubleshooting)의 첫 번째 항목을 보세요.

**Q15. 폴더를 다른 곳으로 옮겨도 되나요?**

됩니다. 폴더째 옮기세요. 폴더 이름에 `^` 나 `%` 가 있어도 `시작.bat` 은 동작합니다(2026-10-28 수정). 다만 `%PATH%` 처럼 존재하는 환경 변수 이름을 `%` 로 감싼 폴더 이름은 윈도우가 먼저 바꿔 버려 실행되지 않습니다.

**Q16. 설정 파일을 직접 고쳐도 되나요?**

권장하지 않습니다. 허용 목록을 사람이 아닌 방법으로 바꾸는 길이 되므로, 키트는 이상한 값이 보이면 모두 "거부" 쪽으로 처리합니다.

**Q17. 오픈소스인가요? 회사에서 써도 되나요?**

### 설명서 html 만들기

설명서의 원본은 `README.md` 와 `README.en.md` 입니다. html은 아래 도구로 만들며, 손으로 고치지 않습니다.

```text
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Readme.ps1 -Check
```

첫 줄은 html 두 개를 다시 만들고, 둘째 줄은 만들지 않고 최신인지만 확인합니다(다르면 종료 코드 1).

### 빌드 방법

컴파일하거나 묶는 빌드 단계가 **없습니다.** 스크립트 파일을 그대로 실행하고, C# 조각은 실행할 때 자동으로 컴파일됩니다. 문서의 html만 위의 `tools\Build-Readme.ps1` 로 만듭니다.

### 배포와 저장소 운영 (GitHub)

- 저장소: GitHub의 비공개(private) 저장소입니다. 공개 전환은 소유자가 직접 결정하며, 공개 전에 개인 식별 정보(시험용 방 이름, 로컬 경로)와 카카오 약관 위험을 다시 점검해야 합니다.
- 브랜치: 기본 브랜치 `main` 에 직접 올리지 않고, 작업 브랜치에서 풀 리퀘스트(PR)를 거쳐 합칩니다.
- 올리지 않는 것: 세션 기록, 체크포인트(`CHECKPOINT.md`), 개발 도구 폴더(`.remember`, `.sodam-re`), 비밀 값(`.env`, 키 파일)은 `.gitignore` 로 제외합니다.
- 줄 끝 규칙: `.gitattributes` 가 `.bat`·`.cmd` 는 CRLF, 나머지 글자 파일은 LF 로 고정합니다. 받은 PC의 git 설정과 상관없이 시험이 같은 결과가 나오게 하기 위한 것입니다.
- 릴리스(Release): 아직 만들지 않았습니다. 7~13단계가 끝난 뒤 정식 버전 번호와 함께 만들지 결정합니다.

### 개발 규칙 (자동 시험이 강제하는 것)

- `.ps1` 은 UTF-8 BOM 포함, `.bat` 과 `.cmd` 는 BOM 없음 + CRLF. 파일을 쓴 뒤 `tools\Write-Bom.ps1 -All` 로 보정합니다.
- `throw` 가 있는 모든 함수의 첫 문장은 `$ErrorActionPreference = 'Stop'` 입니다(호출한 쪽의 오류 설정 때문에 안전장치가 무시되는 것을 막기 위해서입니다).
- 허용 키는 `Ctrl+S`, `Ctrl+V`, `Ctrl+A`, `Ctrl+C`, `Enter` 뿐이며 `Esc` 코드는 없어야 합니다.
- 실제 카카오톡을 조작하는 시험은 환경 변수 `KAKAO_E2E=1` 일 때만 실행되고, 시험 방은 본인 혼자 있는 방만 씁니다(7단계부터).
- 정적 분석(PSScriptAnalyzer)은 설치되어 있지 않아 실행하지 못했습니다.

## 19. 용어 풀이

| 용어 | 쉬운 설명 |
|---|---|
| 터미널 / 명령 프롬프트(cmd) | 글자로 컴퓨터에게 일을 시키는 검은 창입니다. |
| PowerShell | 윈도우에 들어 있는, 글자로 일을 시키는 또 다른 도구입니다. 이 키트가 안에서 사용합니다. |
| 명령줄(CLI) | 마우스 대신 글자(명령)를 입력해서 프로그램을 쓰는 방식입니다. |
| `.bat` / `.cmd` 파일 | 더블클릭하면 정해진 명령을 차례로 실행해 주는 파일입니다. |
| 종료 코드 | 프로그램이 끝날 때 남기는 결과 번호입니다. 0은 성공입니다. |
| UAC | 프로그램이 관리자 권한을 요청할 때 뜨는 허락 창입니다. 이 키트는 띄우지 않습니다. |
| 클립보드 | 복사(`Ctrl+C`)한 내용이 잠깐 머무는 곳입니다. |
| 허용 목록 | 키트가 다룰 수 있도록 사람이 미리 허락한 방의 명단입니다. |
| 문지기(가드) | 키 입력을 보내기 직전에 "맞는 창인지" 등을 확인하고 틀리면 멈추는 안전장치입니다. |
| 내보내기 | 카카오톡의 공식 기능으로 대화를 글자 파일로 저장하는 것입니다. |
| 파서 | 글자 파일을 읽어서 "누가, 언제, 무슨 말을 했는지"로 나눠 주는 부분입니다. |
| 로그(기록) | 언제 무엇을 했는지 한 줄씩 남기는 기록입니다. 이 키트는 대화 본문을 남기지 않습니다. |
| JSON | 컴퓨터끼리 주고받기 쉬운 정리된 글자 형식입니다. AI가 결과를 읽을 때 씁니다. |
| 환경 변수 | 윈도우에 저장된 이름표 붙은 설정값입니다. |
| BOM | 글자 파일 맨 앞에 붙는 보이지 않는 표시입니다. 윈도우 PowerShell이 한글 파일을 바르게 읽는 데 필요합니다. |
| 스냅샷 | 어느 순간의 내용을 그대로 저장해 둔 사본입니다. |
| 오탐 | 문제가 아닌데 문제라고 잘못 판단하는 것입니다. |
