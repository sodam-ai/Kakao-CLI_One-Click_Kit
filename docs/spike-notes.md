# 스파이크 기록 (이 PC: Windows 11, 화면 언어 en-US, PowerShell 5.1)

각 작업의 "먼저 확인할 것"의 결과를 사실만 적는다. 틀린 가정은 후퇴 방안과 함께 적는다.

## Task 1 — 한글 깨짐 (2026-10-27)

**결과: 문제 없음.** 조건을 지키면 한글이 정상으로 보인다.

- `.bat`/`.cmd`: UTF-8 **BOM 없음** + CRLF, 두 번째 줄에서 `chcp 65001 >nul`. (첫 줄 `@echo off`는 ASCII라 안전)
- `.ps1`: UTF-8 **BOM 포함**. BOM이 없으면 PowerShell 5.1이 한글을 cp949로 읽어 깨진다.
- `src/kakao.ps1` 맨 위에서 `[Console]::OutputEncoding`을 UTF-8(BOM 없음)로 맞춘다. 상위 프로그램이 UTF-8로 읽으면 한글이 그대로 온다.
- 이 PC의 기본 터미널은 **Windows Terminal**이다. `cmd /c start "" 시작.bat`으로 연 창에서 한글(`카카오톡 키트`)이 정상 표시됨을 그 창만 캡처해 눈으로 확인했다(캡처는 삭제).
- 관리자 권한(UAC) 창은 뜨지 않았다.
- **함정:** `pause`는 시스템 언어(영어)로 "Press any key to continue . . ."를 출력한다. 요구 ②(영어 메뉴 금지)에 어긋나므로 `echo 한글 안내` + `pause >nul`로 바꿨다. 메뉴(Task 11)에서도 `pause` 단독 사용 금지.
- 한글 파일 이름(`시작.bat`)은 `cmd /c`와 PowerShell `Start-Process`에서 그대로 열린다.

## Task 4 — Win32 입력 계층 (2026-10-27)

**결과: 진짜 Win32 호출이 가짜 제공자와 같게 동작한다(읽기 전용으로 확인, 입력은 보내지 않음).**

- `EnumWindows`로 카카오톡 프로세스의 보이는 최상위 창 3개를 읽었다: 비밀방 채팅 창(제목이 방 이름과 **정확히 일치**), 메인 창(`카카오톡`, 4글자), 제목 없는 작은 창 1개. 클래스는 모두 `EVA_Window_Dblclk`. 제목 없는 창은 `ExpectedTitle`이 비어 있지 않은 한 가드를 통과할 수 없다.
- 보조 모니터의 **음수 좌표**(예: 왼쪽 -2174)도 `GetWindowRect`로 정상 읽힘. 클릭 좌표는 `왼쪽 + 비율 × 너비`로 계산하므로 음수 좌표에서도 동작한다.
- `GetLastInputInfo` 기반 "사람 손 감지"는 시험에서 가짜로만 검증했다. 진짜 입력을 보낸 직후 값이 바뀌는 정도(오탐)는 Task 8의 E2E에서 확인한다. 오탐이 잦으면 보내기 직후 30ms 대기값을 늘린다.
- **PowerShell 함정:** 명령 인자 자리에 쓴 `0x0002` 같은 16진수는 숫자가 아니라 문자열로 넘어간다(변수로 넘긴 값은 정상). 마우스 이벤트 값은 변수에 담아 넘긴다.
- 시험(`KAKAO_KIT_HOME`)은 진짜 키트와 같은 뮤텍스를 쓰지 않도록 잠금 이름에 경로를 붙인다.
