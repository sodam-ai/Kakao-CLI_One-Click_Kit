# VerifySent 확인 라운드 순서 (제안, 아직 시작하지 않음)

목적: 보낸 글이 방에 나타났는지 **카카오톡 공식 내보내기(`Ctrl+S`)** 로 확인하는 부분을 만들 수 있는지 실제 카카오톡으로 확인합니다.
이 확인 장치가 없으면 `Ready` 를 켜는 순간 모든 전송이 "불명"이 되어 같은 글을 다시 보내게 되므로, `Ready` 는 이 라운드가 끝날 때까지 꺼 둡니다.
(UI 자동화로는 메시지 목록을 읽을 수 없다는 것이 2026-11-15 조사에서 확인되었습니다.)

## 이미 있는 것 (카카오톡 없이 시험됨)
- 내보낸 파일 읽기: `ConvertFrom-KakaoExport`(Parse.ps1), 보관·읽기·검색(Export.ps1, Search.ps1)
- 판정: `Find-SentMessageInExport`(Verify.ps1, 시험 9개). 보낸 분 이후에 같은 글이 있을 때만 `confirmed`, 아니면 `unknown`. 보낸 사람 구분이 없는 방은 항상 `unknown`.
- 키: `Ctrl+S`, `Ctrl+V`, `Enter` 는 이미 허용 목록에 있습니다. **새 키는 없습니다.** 새로운 것은 "저장 창"이라는 새 대상 창뿐입니다.

## 공통 규칙 (docs/human-rounds-s6a-m8.md 의 공통 규칙을 그대로 따름)
- `테스트방`(나 혼자 있는 오픈채팅)에서만. 라운드마다 사람이 "D1 60초 시작" 처럼 승인해야 시작합니다.
- 클립보드는 저장 → 사용 → 복원(복원 실패 또는 글이 아닌 내용이면 중단). 내용은 기록·문서에 남기지 않습니다.
- 사람이 키보드·마우스에 손대면 입력 전에 멈춥니다. 대상 창 제목·프로세스가 다르면 입력 0.
- 저장 파일은 키트 데이터 폴더 아래 임시 이름(영문·숫자)만 씁니다. 파일 이름 칸에 포커스가 있다고 읽히지 않으면 **경로를 붙여넣지 않습니다**(그냥 Enter 를 치면 카카오톡이 정한 기본 폴더에 방 이름으로 저장되어 흔적이 남기 때문).

## 라운드 D1 — 저장 창 읽기 (입력 1개: `Ctrl+S`, 글 입력 없음)
1. 방 창을 키트가 `Enter` 로 열거나 사람이 열어 둔 상태에서 시작합니다.
2. AI 입력: `Ctrl+S` 1번. 그 뒤 **읽기만**: 새 창 제목, 파일 이름 입력칸의 존재와 키보드 포커스(HasKeyboardFocus), 현재 폴더 표시, 확장자·형식 칸.
3. 저장 창은 `PostClose`(제목·프로세스 확인 뒤 닫기 요청, 키 없음)로 닫고, 닫힌 것과 방 창이 그대로인 것을 확인합니다.
4. 알아내는 것: 저장 창이 뜨는 데 걸리는 시간, 파일 이름 칸에 포커스가 처음부터 있는지, 저장 뒤 확인 창이 따로 뜨는지(이 라운드에서는 저장하지 않으므로 D2 에서).
- 통과 기준: 저장 창 1개가 열리고 파일 이름 칸이 읽히며, 닫은 뒤 창 목록이 시작 때와 같음.
- 멈춤 기준: 3초 안에 저장 창이 없음 / 제목이 예상과 다름 / 파일 이름 칸을 못 찾음 → 더 입력하지 않고 닫기 요청만.

## 라운드 D2 — 실제로 저장하고 읽기 (입력 3개: `Ctrl+S`, `Ctrl+V`, `Enter`, 메시지는 보내지 않음)
1. D1 에서 파일 이름 칸에 포커스가 있었을 때만 진행합니다.
2. `Ctrl+S` → (파일 이름 칸 포커스 재확인) → 클립보드에 임시 경로를 넣고 `Ctrl+V` → `Enter`.
3. 10초 안에 그 경로에 파일이 생기는지 확인하고, `ConvertFrom-KakaoExport` 로 읽어 머리글의 방 이름이 같은지 확인합니다. 방에 이미 있는 시험 글이 읽히는지 봅니다.
4. 저장 뒤 남는 창(완료 알림 등)이 있으면 제목·프로세스 확인 뒤 닫기 요청으로만 닫습니다.
5. 알아내는 것: 한글 아닌 경로에서도 저장되는지, 확장자가 `.txt` 로 붙는지, 이모지·여러 줄·시간 표기(오전/오후)가 예상 형식인지, 저장에 걸리는 시간.
- 통과 기준: 파일이 생기고 파서가 읽으며 방 이름이 같고 클립보드가 원래대로 돌아옴.
- 멈춤 기준: 파일이 안 생김 / 읽을 수 없음 / 방 이름 불일치 / 클립보드 복원 실패 → 보고하고 중단(재시도 없음).

## 라운드 D3 — 보내고 확인하기 (**별도 "M8 승인" + 범위 지정 필요**: 시험방에 한 줄 1번)
1. D2 가 통과한 뒤에만 합니다. 열기(`Enter`) → 초안 없음 확인 → 입력란 포커스 확인(Confirm-InputFocus) → 붙여넣기 + `Enter` → 저장 → `Find-SentMessageInExport`.
2. 기대: `confirmed`, `Matches` 가 1. 2 이상이면 중복 전송 의심으로 보고.
3. 이 라운드에서 처음으로 `Confirm-InputFocus` 가 실제 포커스를 참으로 읽는지도 확인합니다(지금까지는 거짓만 읽음).
- 통과 기준: 한 줄이 방에 1번 나타나고 판정이 `confirmed`, 클립보드 복원, 방 창과 저장 창이 정리됨.

## 라운드가 모두 통과한 뒤에 코드에서 바뀌는 것 (그 전에는 바꾸지 않음)
- 내보내기를 하는 부품(`Ctrl+S` → 경로 붙여넣기 → `Enter` → 파일 대기)과 `VerifySent` 연결을 만듭니다(시험 먼저).
- `$script:SendVerifySentImplemented` 를 참으로 바꿉니다. **`SendReadyApproved` 는 사람이 열기로 정할 때까지 계속 거짓입니다.**
- 5342 를 검증 목록에 넣는 것은 계속 사람 결정입니다.

## 남는 위험
- 표본이 1회·이 PC·이 버전·한국어 화면·100% 배율뿐입니다. 저장 창의 구조가 다른 환경에서는 다를 수 있어 그 경우 멈춥니다(안전한 쪽).
- 같은 분 안에 같은 글이 이미 있으면 거짓 확인이 될 수 있습니다(`Matches` 로 드러남).
- 내보내기는 대화 전체를 파일로 만들므로 파일에 대화 내용이 들어갑니다. 라운드에서 만든 임시 파일은 키트 데이터 폴더 안에만 두고, 라운드가 끝난 뒤 지우는 일은 사람이 합니다(이 라운드에서 AI 는 파일을 지우지 않습니다).
