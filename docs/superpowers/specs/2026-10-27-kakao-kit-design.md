## 1. 목적과 이유

- 코딩 경험이 없는 사람도 `.bat` 하나로 카카오톡 PC(Windows)의 **읽기·보내기**를 쓸 수 있게 하고, AI(Claude Code 등)도 같은 기능을 명령줄(CLI)로 부를 수 있게 한다. **[확정]**
- 참고 저장소 `silver-flight-group/kakaocli`는 **macOS 전용**이라(Swift, 접근성 API `AXUIElement`, 키체인, 맥 장치 UUID로 DB 암호키 도출) Windows에서 쓸 수 없다. 그래서 같은 기능을 Windows 카카오톡용으로 **새로 만든다.** **[확정: 사용자가 Mac 없음 → 신규 개발 선택]**
- 카카오톡에는 공식 명령줄 기능이나 API가 없다. 따라서 이 키트는 카카오톡 창에 **키 입력과 클릭을 대신 입력**하는 방식으로만 동작한다. 사용자는 명령 한 줄만 입력하고, 단축키·클릭·창 열기는 도구가 내부에서 한다. **[확정]**

## 2. 사용자

1. **비개발자(주 사용자)**: 번호 메뉴가 있는 한글 `.bat`으로 설치, 실행, 점검, 제거까지 한다.
2. **AI 에이전트**: `kakao <명령> --json`으로 호출한다.

## 3. 목표 / 비목표 / 안티목표

**목표**
- 지정한 방에 메시지 보내기, 대화 읽기(전체 기록은 공식 내보내기), 키워드 검색, 환경 점검, 설치·업데이트·제거를 쉬운 한글 화면으로 제공한다.
- 어떤 오류든 비개발자가 이해할 한글 설명과 로그 파일이 남는다.
- 제거하면 키트가 만든 것만 지우고 카카오톡 앱과 대화 데이터는 건드리지 않는다.

**비목표 (v1에서 하지 않음)**
- 카카오톡 DB 복호화, 프로토콜(LOCO) 분석, 앱 변조·디컴파일 일체. (이용약관 2.2조: 리버스엔지니어링·디컴파일·디스어셈블 금지. 설치 폴더 `EULA_ko.txt`로 확인) **[확정: 방식 C 제외]**
- 실시간 감시(kakaocli의 `sync --follow`), 자동 답장 봇, 여러 방에 일괄 전송. **[내 판단]**
- 이미지·파일 등 비텍스트 메시지 읽기/보내기.
- 카카오톡이 아닌 다른 메신저, macOS.

**안티목표 (기술적으로 동작해도 실패로 보는 것)**
- 허용하지 않은 방에 입력이 가는 것, 의도하지 않은 전송, 대화 삭제나 방 나가기가 눌리는 것.
- 사용자의 클립보드나 카카오톡 상태를 망가뜨리는 것.
- 비밀번호나 대화 내용이 로그, 화면, 외부로 새는 것.

## 5. 검토한 방식 (Approaches)

**읽기(사용자가 선택)**

| 방식 | 장점 | 단점 | 결과 |
|---|---|---|---|
| A. 화면 자동화(접근성 API/OCR/복사) | 약관 위험 낮음 | 화면에 보이는 것만, 접근성 API로는 글자가 거의 안 읽힘 | 보내기·방 열기에 사용 |
| B. 공식 내보내기(Ctrl+S) | 리버스엔지니어링 없음, **전체 기록**(311줄/11,077자 vs 복사 1,428자) | 실시간 아님, 저장 대화상자 자동화 필요 | **읽기 주력 선택** |
| C. DB 복호화 | 빠름, 실시간 | 약관 2.2조 충돌, 계정 제한 위험 | **제외** |

| 방식 | 장점 | 단점 |
|---|---|---|
| ① `.bat` + 내장 PowerShell 5.1 (**선택**) | 설치할 것이 없음. winget·pwsh·관리자 권한이 없는 이 PC에서 그대로 동작. 설치=폴더 복사, 제거=폴더 삭제 | PowerShell 5.1은 오래된 문법, 한글 인코딩 주의 필요 |

## 6. 기능 명세

### 6.1 CLI 명령 (`kakao`)

| 명령 | 동작 | kakaocli 대응 |
|---|---|---|
| `kakao status` | 환경 점검: 카카오톡 설치·버전·실행·로그인 상태, 허용 방 수, 모니터/DPI, 최근 오류 | `status`, `auth`, `login --status` |
| `kakao rooms list` / `add <이름>` / `remove <이름>` | 허용 목록 관리. `add`는 카카오톡 검색에서 **이름이 정확히 일치하는 1건**일 때만 등록 | `chats` |
| `kakao open <방>` | 허용 목록 방만. 검색 → 열기 → 창 제목 확인 | (내부 동작) |
| `kakao send <방> "<메시지>" [--dry-run] [--yes]` | 보내기. 기본은 미리보기 + 확인 | `send` |
| `kakao export <방> [--out 폴더]` | 공식 내보내기로 전체 기록 저장 | (신규) |
| `kakao read <방> [--since 7d] [--last N] [--json]` | 내보내기 → 파싱 → 출력 | `messages` |
| `kakao search "<키워드>" [--room <방>]` | 저장된 내보내기 파일에서 검색(카카오톡 조작 없음) | `search` |
| `kakao version` / `help` / `update` / `uninstall` / `menu` | 아래 6.3 참고 | — |

kakaocli의 `sync --follow`, `harvest`, `query`, `schema`, `inspect`는 **v1 제외**다. DB가 없어서 해당 없거나(`query`, `schema`), 실시간·대량 조작이라 위험하다(`sync`, `harvest`). **[내 판단]**

### 6.2 원클릭 메뉴 (`시작.bat`) — 사용자 지시 반영 (2026-10-27) **[확정: 4개 요구]**

**사용자 요구 4개**
1. **관리자 권한 창(UAC)이 절대 뜨지 않는다.** 관리자 권한을 요청하지 않는다(`-Verb RunAs` 금지, 레지스트리는 `HKCU`만, `Program Files`·서비스·작업 스케줄러 등록 금지). 인수 시험에 "UAC 창이 한 번도 안 뜸"을 넣는다.
2. **영어 메뉴는 한국어로 쓰거나 영어 옆에 한국어를 병기한다.** 메뉴 이름은 한글이 먼저, 명령 이름은 괄호로 병기한다(예: `보내기 (send)`). 오류·안내·도움말은 한글만 쓴다.
3. **메뉴 진입 단계를 최소화한다.**
4. **메뉴 구성은 간단하면서도 자세하게 한다.**

**진입 단계를 줄이는 규칙 [내 판단]**
- **설치 단계 없음**: 압축을 푼 폴더에서 `시작.bat`을 더블클릭하면 첫 실행 때 자동 점검과 설정을 하고 곧바로 메인 메뉴로 간다. (프로그램은 그 폴더에서 실행, 사용자 데이터만 `%LOCALAPPDATA%\KakaoKit`)
- **숫자 한 번만 누르면 실행**(엔터 불필요, `choice` 명령 사용). 자주 쓰는 방은 글자 한 번으로 바로 선택.
- **메인 화면에 상태를 보여준다**(카카오톡 로그인, 버전 검증 여부). 문제가 있을 때만 "고치기"로 안내하므로 정상일 때는 점검 단계를 거치지 않는다.
- **보내기는 입력 4번**: `1` → 방 선택(마지막에 쓴 방이 기본, 엔터) → 메시지 입력 + 엔터 → `Y`. 본인 혼자만 있는 방은 확인 생략을 선택할 수 있다.
- **고급·가끔 쓰는 기능은 "더 보기" 한 곳에 모은다**(버전, 업데이트, 도움말, 제거).

**메인 화면 (초안)**
```
================================================================
  카카오톡 키트 (Kakao Kit)  v1.0
  카카오톡: ✅ 로그인됨   버전 26.9.0.5337 ✅ 검증됨
================================================================
  자주 쓰는 방:  [A] 비밀방    [B] 나와의 채팅
----------------------------------------------------------------
  1. 메시지 보내기 (send)
  2. 대화 읽기 (read)
  3. 대화 검색 (search)
  4. 대화를 파일로 저장 (export)
  5. 내 방 관리 (rooms)          허용할 방 추가·삭제
  6. 점검·고치기 (status)        로그인·실행 상태 확인
  7. 더 보기                     버전·업데이트·도움말·제거
  0. 종료
----------------------------------------------------------------
  숫자 하나만 누르세요 (엔터 필요 없음)
```
**"더 보기" 화면**: `1 버전 확인 (version)` · `2 업데이트 (update)` · `3 도움말 (help)` · `4 카카오톡 실행·로그인 안내 (login)` · `5 제거 (uninstall)` · `0 뒤로`

**요구 1의 구현 근거**: 압축을 푼 폴더에서 실행하고 사용자 폴더(`%LOCALAPPDATA%`, `HKCU`)에만 쓰면 관리자 권한이 필요 없다(이 PC도 관리자 권한이 아니고 winget이 없음 **[확인됨]**). 본인 PC에서 직접 만든 파일은 인터넷 다운로드 표시가 없어 SmartScreen 경고도 뜨지 않는다 **[내 판단, 배포 때는 별도 검토]**.

**첫 실행**: 위험·면책 안내를 한 번 보여주고 동의를 받는다(동의 전에는 어떤 명령도 실행하지 않음).

## 7. 안전 규칙 (반드시 지킬 것)

1. **허용 목록만**: 방 이름은 정확히 일치해야 한다. 근사 일치는 없다.
2. **입력 직전 3중 확인**: 대상 창이 KakaoTalk 프로세스 소유이고, 창 제목이 방 이름과 정확히 같고, 포그라운드인 것을 확인한다. 하나라도 틀리면 **키·클릭을 하나도 보내지 않고** 중단한다. (시험 중 터미널이 포커스를 가져가 이 가드가 실제로 키 전송을 막았다 **[검증됨]**)
3. **메뉴 클릭 금지**: ≡ 메뉴 안에 "대화 내용 모두 삭제"와 "채팅방 나가기"가 바로 옆에 있다. 단축키만 쓴다. **허용 키는 다섯 개뿐이다: Ctrl+S, Ctrl+V, Ctrl+C, Ctrl+F, Enter** (2026-11-13 동기화: Ctrl+F 는 통합검색, 2026-11-12 사용자 승인으로 추가). **Ctrl+A 는 쓰지 않는다**: 카카오톡 메인 창에서 Ctrl+A 는 "전체 선택"이 아니라 "친구 추가"(450x690 창)를 연다(2026-11-12 사고, 사용자 스크린샷의 툴팁으로 확인). **Esc 금지**: 카카오톡에서 Esc는 채팅 창을 닫는다 **[검증됨, 실수 사례]**.
4. **보내기**: 한 번에 한 방·한 메시지. 기본은 미리보기 + 확인. `--yes`가 있어야 비대화형 전송을 한다. 최대 길이와 최소 전송 간격(2초)을 둔다. 일괄·반복 전송은 없다.
5. **클립보드**: 텍스트만 저장·복원한다. 이미지·파일 등 비텍스트가 들어 있으면 복원할 수 없으므로 중단하고 알린다 **[내 판단]**.
6. **방 열기는 검색으로만**: 이 계정은 안 읽은 메시지가 300개 넘는 방이 수십 개라 목록을 눈대중으로 클릭하면 엉뚱한 방을 열어 읽음 처리할 수 있다. 검색 결과가 정확히 1건이 아니면 중단한다.
7. **동시 실행 방지**: 하나의 잠금(mutex)으로 두 번째 실행은 거부한다. 실행 중에는 "마우스·키보드를 만지지 마세요" 안내를 한다.
8. **개인정보**: 로그에는 메시지 본문을 남기지 않는다(시간, 명령, 방 이름, 결과만). 내보내기 파일은 사용자 PC의 키트 폴더에만 저장하고 외부로 보내지 않는다. 비밀번호는 다루지 않는다.
9. **읽음 표시 고지**: 일반 방을 열면 상대에게 읽음 표시가 뜬다. 허용 목록에 방을 추가할 때 한 번 알리고 동의를 받는다.

## 13. 검토자 질문에 대한 정리 (2026-10-27)

**13.1 "검색 결과 정확히 1건"을 어떻게 확인하나 (안전 규칙 6 보완)**
- 메인 창은 글자가 안 읽히므로(9장) 확인을 **2겹**으로 한다. ① 열기 전: 검색 결과 영역을 캡처해 한국어 OCR(`ko`)로 읽어 방 이름이 정확히 한 줄 있는지 본다(이 PC에는 `ko`가 있음 **[검증됨]**). ② 연 직후: 창 제목이 허용 목록 방 이름과 **정확히 같은지** 확인한다. 다르면 아무 입력도 하지 않고 중단한다.
- OCR 언어가 없는 PC에서는 ①을 건너뛰고 ②만 쓴다. 이때 남는 위험(첫 줄이 다른 방일 때 그 방이 읽음 처리됨)을 `status`에 경고로 표시하고, `rooms add` 때 같은 이름의 방이 하나뿐인지 사용자가 눈으로 확인하게 한다.
- 검색은 **탭 범위 안에서만**(예: 오픈채팅 탭) 한다. 친구·메시지 본문 검색 결과(통합검색)는 "결과"로 치지 않는다.

**13.2 이미 열려 있는 창, 임시 저장 글(초안), 정리**
- 대상 방 창이 이미 열려 있으면 **재사용**하되, 보내기 전에 입력란이 비어 있는지 확인한다(입력란에서 Ctrl+A → Ctrl+C로 센티널 문자열이 바뀌는지 본다). 비어 있지 않거나 확인이 불확실하면 **중단**하고 "작성 중인 글이 있어서 보내지 않았습니다"라고 알린다. 이 확인 방식은 **[미검증]**이라 builder가 먼저 시험하고, 안 되면 "이미 열려 있으면 중단"으로 후퇴한다.
- **[내 판단, 2026-11-13: 후퇴안을 기본으로 한다]** Ctrl+A 는 허용 키가 아니고(7장 3번) 채팅 입력란에서 전체 선택으로 동작하는지도 확인된 적이 없다. 그래서 **보내기에서는 키트가 직접 연 창에만 보낸다.** 대상 방 창이 이미 열려 있으면(`OpenedByKit=$false`) 입력 0으로 중단하고 "이미 열려 있는 방이라 보내지 않았습니다. 창을 닫고 다시 하세요"라고 알린다. 읽기·내보내기는 이미 열린 창을 재사용해도 된다(입력란을 만지지 않는다). 초안 확인용 입력이 나중에 필요하면 키를 늘리기 전에 사용자 승인과 화면 확인을 먼저 받는다.
- 키트가 **직접 연 창만** 작업 후 닫는다(Esc 금지, 창 닫기 메시지 `WM_CLOSE` 사용: 입력 이벤트가 아님). 원래 열려 있던 창은 그대로 둔다. 메인 창 검색어는 지우고 탭은 원래대로 돌린다.
- 가드가 중간에 멈추는 바람에 저장 대화상자가 남으면 그 대화상자 창에만 `WM_CLOSE`를 보내 닫는다(채팅 창에는 Esc 안 씀).

**13.3 검증 안 된 카카오톡 버전**
- 경고만 하지 않고 **읽기 전용 모드**로 내린다(`send` 잠금). 사용자가 `--allow-unverified`를 직접 붙일 때만 보내기가 풀린다. (이 PC 버전 26.9.0.5337만 검증됨)

**13.4 내보내기 파일 수명**
- 방마다 `latest.txt` 1개 + 최근 스냅샷 3개를 보관한다(기본). `search`는 `latest.txt`만 대상으로 해서 중복 결과를 막는다. 30일 지난 스냅샷은 자동 정리한다.
- `update`는 내보내기·설정·로그를 보존한다. `uninstall`은 키트 파일만 지우고, 내보내기 폴더는 **"사적인 대화가 들어 있습니다. 함께 지울까요? (기본: 남김)"**로 물어본다. 말없이 지우면 되돌릴 수 없고 말없이 남기면 사적 대화가 방치되므로 사용자가 선택하게 한다.

**13.5 시험 방 (사용자 확인 대기)**: 4번 결정의 "비밀방만"은 지나치게 좁았다. 본인 혼자만 있는 **"나와의 채팅"**도 안전한 시험 방이므로 추가하는 안을 아래 질문 3으로 확인한다.

**13.6 사용자 답변이 없어 권고안을 기본값으로 적용한 항목 [내 판단: 가장 안전한 쪽] — 문서 승인 때 바꿀 수 있음**
- **배포 범위**: v1은 **본인 PC 전용**. 다른 사람에게 배포하는 데 필요한 포장, SmartScreen·백신 대응, 다른 PC·다른 Windows 언어 검증, 배포용 면책 강화는 v2 후보로 미룬다. 배포하면 약관·계정 제재 위험이 사용자 전체로 퍼지므로 별도 검토가 필요하다.
- **AI 호출자 권한**: 허용 목록 추가·삭제와 동의는 **사람만**(메뉴에서만, 명령 옵션으로는 불가). 방마다 **"AI 읽기 허용"**, **"AI 보내기 허용"** 스위치를 따로 두고 **기본은 꺼짐**. 스위치를 켤 때 "읽은 내용이 AI 서비스로 전달되어 PC 밖으로 나갈 수 있음"을 알리고 동의를 받는다. 동의 전에는 모든 명령이 실행을 거부한다.
- **시험 방과 방 유형**: 시험은 본인 혼자만 있는 방 2곳(**"비밀방"**, **"나와의 채팅"**)에서만 한다. 친구가 있는 일반 1:1·그룹 방은 **"미검증 유형"**으로 표시하고 **읽기만 허용, 보내기 잠금**(사람이 직접 풀어야 함)으로 시작한다. 동의해 주는 친구와 시험할 수 있게 되면 그때 검증 유형으로 승격한다.

**13.7 보내기 결과 3상태와 중복 전송 방지 (2026-10-30 추가) [내 판단 — 참고 저장소 kakaocli 분석 반영, 바꾸고 싶으면 알려 주세요]**
- 보내기 결과는 셋 중 하나다: **확인됨**(보낸 글이 방에 나타난 것을 확인함), **실패**(입력을 보내기 전에 안전장치가 멈췄거나 입력이 거부된 것이 분명함), **불명**(입력을 보냈으나 결과를 확인하지 못함: 시간 초과, 중간 중단, 확인 읽기 실패).
- **불명이면 자동 재시도를 하지 않는다.** 같은 글을 다시 보내면 중복 전송이 될 수 있기 때문이다. 사용자에게 "보내졌는지 확인하지 못했습니다. 방에서 직접 확인해 주세요"라고 알리고, 재시도는 사람이 확인한 뒤 명시적으로 한다. 종료 코드는 실패와 구분한다(번호는 M8 에서 정함, 후보 5).
- 전송 시도마다 고유 번호를 만들어 기록하고(본문은 남기지 않음) 같은 번호의 재실행은 거부한다. 저장 방식은 2초 간격을 프로세스 사이에서 지키는 방법(결함 D-13)과 함께 M8 에서 정한다.
- 입력란에 이미 글(초안)이 있으면 보내지 않는다(13.2 와 같음).
- 확인 방법: 전송 뒤 공식 내보내기(M9)로 마지막 메시지를 읽어 대조한다. M8 단계에서는 이 확인이 없으므로 입력이 나간 뒤의 결과는 기본적으로 '불명'으로 두고, M9 가 연결되면 '확인됨'을 채운다.
- 근거: 참고 저장소 kakaocli 는 엉뚱한 방으로 가거나 전송이 멈추는데도 `--dry-run` 은 통과하는 사고가 보고되었고(이슈 #9, PR #23·#29), 그쪽의 안전한 전송 PR 은 같은 결과 분류(확인됨/불명)를 쓴다. 코드는 가져오지 않고 아이디어만 참고한다.

**13.8 포그라운드(맨 앞 창) 규칙 (2026-11-13 추가) [실측 + 내 판단]**
- **실측:** 키트는 백그라운드 프로세스에서 카카오톡을 맨 앞으로 안정적으로 가져오지 못한다. `SetForegroundWindow` 만으로는 안 되고(Windows 의 전면 전환 제한), `AttachThreadInput` 보강도 효과가 없어 되돌렸다. 7장 2번의 "포그라운드인 것을 확인"은 그대로 필수지만, "키트가 맨 앞으로 만든다"는 가정은 틀렸다. S5(방 열기 전체 흐름)는 사용자가 카카오톡 창을 직접 클릭해 맨 앞으로 만든 뒤에야 통과했다.
- **규칙:** 입력 전에 카카오톡이 맨 앞이 아니면 입력 0 으로 기다린다. 사람에게 "카카오톡 창을 한 번 클릭하세요"라고 안내하고, 카카오톡이 2초 연속 맨 앞이면 진행하며, 최대 120초 안에 안 되면 입력 0 으로 중단한다(종료 코드 2). 그 뒤 사용자는 손을 떼야 한다(`Wait-UserIdle`).
- **AI 호출자:** 같은 규칙이다. AI 가 터미널에서 부르면 터미널이 맨 앞이므로 입력 0 으로 멈춘다. 사람이 카카오톡을 클릭해 주어야 한다. 이것은 설계서 2장의 "AI 도 같은 기능을 CLI 로 쓴다"에 대한 **알려진 한계**이며, 완전 무인 실행은 v1 목표가 아니다.
- **[미구현]** 지금 이 대기 로직은 저장소 밖 임시 스크립트에만 있고 `src` 에는 없다. M11(명령 계층)에서 구현한다. 입력 키 목록을 늘려서 푸는 방법(예: Alt 키 눌러 보기)은 사용자 승인과 화면 확인 전에는 쓰지 않는다.

**13.9 저장 단축키 Ctrl+S 의 확인 상태 (2026-11-13 추가) [정정]**
- 9장의 "채팅 창에서 Ctrl+S → 저장 창 → 저장 성공"은 **26.9.0.5337 에서 키트가 아닌 수동 실험으로 확인한 기록**이다. 키트의 입력 경로(SendInput + 가드)로 Ctrl+S 를 보낸 적은 없고(`docs/spike-notes.md`), 현재 설치된 5342 에서도 확인하지 않았다. 공개 자료로도 Ctrl+S 가 저장 단축키라는 근거는 확인되지 않았다(대화 백업은 설정 메뉴로 안내됨).
- 따라서 **S6a 의 첫 입력이 Ctrl+S 하나**이며, 채팅 창 제목이 방 이름과 정확히 같고 맨 앞일 때만 보낸다. 결과 창을 보고 계속할지 정한다. 저장 창 파일 이름 칸에서 Ctrl+A 없이 붙여넣기로 경로가 바뀌는지(기본으로 선택돼 있는지)도 S6a 에서 확인한다. 안 바뀌면 키를 늘리지 않고 멈춘다.
