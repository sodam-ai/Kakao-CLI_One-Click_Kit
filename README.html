1. 이 프로젝트는 무엇인가요?

한 줄 설명: 윈도우(Windows)용 카카오톡 PC 앱을 명령 한 줄 또는 시작.bat 더블클릭으로 다룰 수 있게 만드는 도구 모음입니다.

왜 필요한가요?

카카오톡에는 프로그램이 직접 쓸 수 있는 공식 명령 기능(API)이 없습니다. 그래서 이 키트는 사람이 키보드로 하는 동작(붙여넣기 Ctrl+V, 전송 Enter, 대화 저장 Ctrl+S)을 대신 눌러 주는 방식으로만 동작합니다. 사용자는 두 부류를 생각하고 만들고 있습니다.

  1. 코딩을 모르는 사람: 번호를 누르는 한글 메뉴 화면 (⏳ 예정)
  2. AI 도우미(예: Claude Code): kakao <명령> --json 형태의 명령줄 (⏳ 예정)

만들려는 기능 (목표)

  • 내가 허용한 방에만 메시지 보내기
  • 대화 읽기: 카카오톡의 공식 "대화 내보내기" 기능을 사용
  • 저장해 둔 대화에서 키워드 검색
  • 환경 점검, 설치·업데이트·제거
  • 오류가 나면 비개발자도 이해할 수 있는 한글 설명과 기록(로그)을 남김
  • 제거해도 카카오톡 앱과 대화 데이터는 건드리지 않음

하지 않는 것 (비목표)

  • 카카오톡 대화 저장소(DB)를 해독하거나 앱을 분석·변조하는 방식: 이용약관과 충돌할 수 있어 쓰지 않기로 확정했습니다.
  • 실시간 감시, 자동 답장 봇, 여러 방에 한꺼번에 보내기
  • 사진·파일 같은 글자가 아닌 메시지의 읽기·보내기
  • 카카오톡 외의 메신저, macOS(맥), 스마트폰

참고한 것

macOS 전용 오픈소스 도구(이름: kakaocli)가 있지만 맥에서만 동작해서 윈도우에서는 쓸 수 없었습니다. 그래서 같은 목적을 윈도우용으로 처음부터 새로 만들었고, 그 도구의 코드를 가져다 쓰지 않았습니다.

2. 현재 상태: 되는 것과 아직 안 되는 것

개발은 13단계로 나뉘어 있고 지금까지 1~6단계를 끝냈으며 7단계는 부품까지, 9단계는 카카오톡을 건드리지 않는 부분(보관·읽기·검색)의 부품까지 만들었습니다. 표의 "부품 완료"는 그 기능의 부품(함수)이 만들어졌고 자동 시험을 통과했지만, 사용자가 부를 수 있는 명령으로는 아직 연결되지 않았다는 뜻입니다.

4. 다운로드와 설치 방법

다운로드 방법

소스는 GitHub의 비공개(private) 저장소 Kakao-CLI_One-Click_Kit 에 있습니다. 아직 공개 저장소가 아니라서 접근 권한이 있는 사람만 받을 수 있고, 누구나 내려받는 공개 주소는 없습니다. 접근 권한이 있다면 둘 중 한 가지로 받습니다.

  • 방법 가: GitHub 저장소 페이지의 초록색 Code 버튼을 누르고 Download ZIP 을 눌러 압축 파일을 받습니다(영어 화면 기준).

USB나 압축 파일로 폴더를 직접 받았다면 바로 아래 순서로 설치합니다.

설치 방법 (폴더 복사)

  1. 압축 파일(.zip)이면 먼저 완전히 풀어 주세요. 파일을 우클릭해서 "모두 압축 풀기"(영어 윈도우: Extract All)를 고릅니다. 압축 파일 안에서 바로 실행하면 일부 파일만 임시로 풀려 실패합니다.
  2. 풀어 둔 폴더를 원하는 곳에 둡니다. 예: D:\KakaoKit. 짧은 영문·숫자 이름을 권장합니다. 폴더 이름에 %PATH% 처럼 %이름% 꼴은 넣지 마세요(15장의 알려진 한계).
  3. 폴더 안에 시작.bat, kakao.cmd, src 폴더가 보이면 준비가 끝난 것입니다.

지금은 업데이트 명령이 없습니다(update 는 ⏳ 예정). 새 폴더를 받았다면 기존 폴더를 새 폴더로 바꿔 쓰면 됩니다. 저장소를 gh repo clone 으로 받았다면 그 폴더 안에서 git pull 을 실행해 최신으로 맞출 수도 있습니다. 설정과 기록을 저장하는 기능이 연결된 뒤에는 그것들이 사용자 폴더의 %LOCALAPPDATA%\KakaoKit 에 따로 있어서, 프로그램 폴더를 바꿔도 보존됩니다(⏳).

폴더를 삭제하면 끝입니다. 지금 버전은 폴더 밖에 아무것도 만들지 않습니다. 레지스트리, 바탕화면 바로가기, 시작 메뉴, PATH, 작업 스케줄러 모두 건드리지 않습니다(코드 검색으로 확인했고, 이 PC에 %LOCALAPPDATA%\KakaoKit 폴더가 없는 것도 확인했습니다). 앞으로 설정을 저장하는 기능이 연결되면 그 폴더가 생길 수 있고, uninstall 명령이 안내합니다(⏳). 어떤 경우에도 카카오톡 앱과 대화 내용은 건드리지 않습니다.

방법 3. PowerShell 또는 Windows Terminal

왜 kakao 가 아니라 .\kakao.cmd 인가요?

윈도우에는 현재 폴더의 프로그램을 이름만으로 찾지 못하게 하는 보안 설정(환경 변수 NoDefaultCurrentDirectoryInExePath)이 있습니다. 이 PC에서는 값이 1로 켜져 있어서 kakao version 만 입력하면 "인식할 수 없다"는 오류가 났습니다. PowerShell은 설정과 상관없이 항상 .\ 를 요구합니다. 그래서 어느 환경에서나 통하는 .\kakao.cmd 를 쓰는 것이 안전합니다.

다른 폴더에서 실행하기

전체 경로를 쓰면 어느 폴더에서든 실행됩니다. 예: D:\KakaoKit\kakao.cmd version. 경로에 공백이 있으면 따옴표로 감쌉니다.

환경 변수는 윈도우에 저장된 이름표 붙은 설정값입니다. 키트가 직접 읽는 것은 KAKAO_KIT_HOME 하나뿐이며 모두 선택 사항입니다. 비밀번호나 토큰 같은 비밀 값을 환경 변수나 파일로 받는 기능은 없습니다.

9. 작동 방법 (원리)

큰 그림 (비유)

카카오톡은 공식 출입문(API)이 없는 집입니다. 그래서 이 키트는 사용자 대신 키보드 단축키를 눌러 주는 로봇 손을 둡니다. 다만 로봇 손은 규칙이 엄격한 문지기(가드) 가 허락할 때만 움직이고, 문지기가 조금이라도 의심스러우면 아무것도 누르지 않고 멈춥니다.

세 가지 방식과 선택

방식설명쓰나요?
A. 화면 자동화키보드·마우스 입력을 대신 보냅니다.✅ 보내기와 방 열기에 사용
B. 공식 대화 내보내기카카오톡 자체 기능(Ctrl+S)으로 대화를 글자 파일로 저장한 뒤 그 파일을 읽습니다.✅ 읽기의 중심 방식
C. 저장소 해독·앱 분석카카오톡 내부 데이터를 풀어 읽는 방식입니다.❌ 쓰지 않음 (약관 충돌)

메시지 보내기의 원리 (⏳ 구현은 8단계, 아래 부품은 ✅)

  1. 허용 목록 확인: 방 이름이 글자 그대로 일치하는 방만 통과합니다.
  2. 방 열기: 목록을 눈대중으로 클릭하지 않고 검색으로만 엽니다. 검색 결과가 정확히 1건이 아니면 멈춥니다.
  3. 문지기 확인: 창의 주인이 카카오톡인지, 창 제목이 방 이름과 정확히 같은지, 맨 앞에 있는지, 사람이 키보드·마우스를 만지지 않았는지, 눌려 있는 키가 없는지(한/영 키는 제외) 확인합니다.
  4. 클립보드 저장: 지금 복사해 둔 글(텍스트일 때만)을 안전하게 저장합니다.
  5. 보낼 글을 클립보드에 넣고 정말 들어갔는지 확인합니다.
  6. Ctrl+V 로 붙여넣고 Enter 로 보냅니다.
  7. 클립보드를 원래대로 되돌리고 되돌려졌는지 확인합니다.
  8. 기록(로그)에 시각·명령·방 이름·결과만 남깁니다. 메시지 본문은 남기지 않습니다.

타자를 치는 대신 붙여넣는 이유: 한글·이모지·긴 글도 글자가 빠지거나 바뀌지 않기 때문입니다.

대화 읽기의 원리 (⏳ 구현은 9단계, 파서·보관·읽기·검색 부품은 ✅)

  1. 방을 열고 Ctrl+S 를 누릅니다. 카카오톡의 "다른 이름으로 저장" 창이 뜹니다.
  2. 항상 새 파일 이름을 붙여넣고 Enter 를 눌러 저장합니다(같은 이름이 있어 덮어쓰기 질문이 뜨는 일을 막기 위해서입니다).
  3. 저장된 파일을 읽습니다. 파일의 모양은 첫 줄 <방 이름> 님과 카카오톡 대화, 둘째 줄 저장한 날짜 : YYYY-MM-DD HH:MM:SS, 날짜 구분선 --------------- 2026년 10월 21일 수요일 ---------------, 메시지 [닉네임] [오전 2:59] 내용 입니다.
  4. 보관: 방마다 최신본(latest.txt) 1개와 가장 새 스냅샷 3개만 남기고, 30일이 지난 스냅샷은 지웁니다(✅ 부품, 가짜 파일로 시험됨). 파일의 첫 줄 방 이름이 등록된 방과 다르면 아무것도 저장하지 않고 멈춥니다. 읽기와 검색은 최신본만 보고, AI 는 방마다 AI 읽기가 켜진 곳만 읽을 수 있습니다. 저장 창으로 내보내는 부분과 명령 연결은 ⏳ 입니다.

방 열기의 원리 (⏳ 명령 연결은 7단계, 아래 부품은 ✅)

  1. 허용 목록에 있는 방인지 먼저 확인합니다. 아니면 창 목록조차 읽지 않고 멈춥니다.
  2. 같은 제목의 방 창이 이미 하나 열려 있으면 그 창을 쓰고(키트가 연 것이 아니므로 닫지 않습니다), 둘 이상이면 어느 것인지 알 수 없어 멈춥니다.
  3. 카카오톡 메인 창이 정확히 하나인지, 한국어 글자 읽기(OCR)를 쓸 수 있는지 확인합니다. 하나라도 아니면 열지 않습니다.
  4. 키보드·마우스에서 손이 떨어지기를 기다린 뒤, 검색 아이콘 클릭 → 전체 선택(Ctrl+A) → 방 이름 붙여넣기(Ctrl+V) 순서로 검색합니다. 목록을 눈대중으로 클릭하지 않습니다.
  5. 검색 결과 부분을 화면 글자 읽기로 읽어 방 이름 하나뿐인지 확인합니다. 확인하지 못하면 더블클릭하지 않습니다. 이때 카카오톡 창 크기가 기준과 같은지, 결과 부분이 다른 창에 가려지지 않았는지도 봅니다.
  6. 첫 결과 줄을 더블클릭 1번 하고, 새 창이 최대 8초 안에 생기기를 기다립니다. 새 창의 제목이 방 이름과 글자 그대로 같을 때만 성공입니다.
  7. 제목이 다르면 그 창을 닫고 멈춥니다. 닫는 것은 키트가 연 창뿐이고, 카카오톡 소유이면서 제목이 정확히 같은 창에만 닫기 요청 하나를 보냅니다.

화면 글자 읽기는 화면을 메모리에서만 읽습니다(디스크에 저장하지 않음). 카카오톡 창의 크기와 글자 위치는 창이 놓인 모니터의 화면 배율에 따라 달라지므로(같은 창이 150%에서는 588x753, 100%에서는 392x502), 판정에 쓰는 픽셀 값을 그 배율에 맞춰 바꿔 계산하도록 만들었습니다. 기준과 다르면 열지 않는 쪽으로 멈춥니다. 다만 카카오톡 메인 창은 150% 모니터에 있어도 창 자신의 배율 값이 100%로 나와(2026-11-02 읽기 전용 점검) 그 모니터에서 "기준과 다르다"고 멈추던 결함이 있었고, 창이 놓인 모니터의 배율을 읽도록 2026-11-11에 고쳤습니다(12.3의 10번). 100% 모니터에서는 실제 열기·닫기를 통과했습니다. 방을 열면 상대에게 "읽음" 표시가 뜰 수 있어 되돌릴 수 없으므로, 확인하지 못하면 열지 않는 것이 이 부품의 기본 규칙입니다.

문지기가 막는 것

  • 허용 키 5개(Ctrl+S, Ctrl+V, Ctrl+A, Ctrl+C, Enter) 외에는 어떤 키도 보내지 않습니다.
  • Esc 는 절대 보내지 않습니다. 카카오톡에서 Esc 는 채팅 창을 닫아 버립니다(실제로 겪은 실수입니다).
  • 창 오른쪽 위 ≡ 메뉴는 클릭하지 않습니다. 그 안에 "대화 내용 모두 삭제"와 "채팅방 나가기"가 바로 옆에 붙어 있습니다.
  • "확인"과 "입력"을 한 번의 동작으로 묶어서, 확인한 뒤 입력하기 전 사이에 창이 바뀌는 틈이 없게 했습니다.
  • 입력 직전에 눌려 있는 키가 있으면 입력하지 않습니다. 사람이 키를 누른 채 Ctrl 조합이 나가면 엉뚱한 단축키가 되기 때문입니다. 한/영 키만은 예외입니다. 일부 키보드·입력기에서는 손을 떼도 이 키가 계속 눌린 것으로 읽혀서(이 PC에서 확인), 이것까지 막으면 아무것도 보낼 수 없기 때문입니다. 다른 키는 예외가 없습니다.

12.3 알려진 보안 한계 (숨기지 않고 적습니다)

  1. kakao.cmd 의 인자 해석: 윈도우 cmd가 명령줄을 먼저 해석하기 때문에, 메시지 같은 믿을 수 없는 글을 명령줄 인자에 그대로 이어 붙여 호출하면 & 나 %이름% 이 명령으로 실행될 수 있습니다. 이는 cmd의 구조라 이스케이프로 완전히 막을 수 없습니다. 그래서 메시지 본문은 --file 이나 표준입력으로만 받고, 자동 호출은 powershell -NoProfile -ExecutionPolicy Bypass -File src\kakao.ps1 을 직접 부르도록 할 예정입니다(⏳ 8·11단계). 2026-10-31 직접 확인한 범위: kakao.cmd 에 &·| 가 따옴표 없이 그대로 도착하면 그 뒤의 글이 실제로 명령으로 실행됩니다. 따옴표로 감싼 경우와 src\kakao.ps1 을 직접 부르는 경우(특수문자를 넣어도 실행되지 않음)는 안전하며, 이 두 가지는 시험으로 고정했습니다. 지금은 version 하나뿐이고 입력한 글자를 명령 이름 비교에만 써서 사용자가 직접 칠 때의 위험은 낮지만, 메시지 같은 믿을 수 없는 글을 kakao.cmd 로 넘기면 안 됩니다.
  2. 설정 파일은 일반 글자 파일입니다. 같은 사용자 계정으로 실행되는 사람이나 프로그램이 직접 고치면 허용 목록을 바꿀 수 있습니다. "사람만 변경" 규칙은 명령 수준에서만 지킵니다. 읽기 전용 설정 등은 12단계에서 검토합니다.
  3. KAKAO_KIT_HOME 환경 변수로 데이터 폴더를 바꿀 수 있습니다(원래 시험용). 실제 사용에서도 적용되므로, 기본 폴더가 아닌 곳을 쓰면 명령마다 표시하도록 할 예정입니다(⏳ 11단계).
  4. 키 입력 방식의 실제 동작: 새로 만든 입력 방식(SendInput)으로 클릭, 붙여넣기(Ctrl+V), 더블클릭, 창 닫기는 실제 카카오톡에서 통과했습니다. Enter, Ctrl+S, Ctrl+A 와 다른 키보드·입력기, 사람 손 감지의 오탐(만지지 않았는데 멈춤)은 아직 확인하지 못했습니다(⏳ 7~9단계).
  5. 붙여넣기 직후 클립보드 복원 타이밍: 카카오톡이 붙여넣기를 끝내기 전에 복원하면 원래 클립보드 글이 대신 전송될 위험이 있어, 복원 전에 기다리는 시간을 넣고 실제로 확인할 계획입니다(⏳ 8단계).
  6. 클립보드를 잠깐 잠그는 프로그램: 윈도우 클립보드 기록이나 캡처 도구가 변경 직후 클립보드를 붙잡을 수 있습니다. 키트는 읽기·쓰기 결과를 확인하고 재시도하며, 끝내 안 되면 작업을 멈춥니다.
  7. 같은 계정에서 이미 실행 중인 악성 프로그램은 이 키트가 막을 수 없습니다. 일반적인 한계입니다.
  8. 화면 글자 읽기에 기대는 판정: 방 열기의 '검색 결과가 정확히 1건' 판정은 카카오톡 26.9.1.5339, 오픈채팅 탭, 기준 창 크기에서 잰 값에 기대고 한국어 글자 읽기 엔진의 정확도에 영향을 받습니다. 값이 다르거나 읽지 못하면 열지 않는 쪽으로 멈추도록 만들었고 실제 화면에서 엉뚱한 방이 열린 적은 없지만, 모든 화면을 확인한 것은 아닙니다. 일반 방(1:1·단체방)과 카카오톡이 다시 바뀐 화면에서는 다시 확인해야 합니다.
  9. 방 열기는 되돌릴 수 없는 일입니다: 방을 열면 상대에게 '읽음' 표시가 뜰 수 있습니다. 그래서 허용한 방, 검색 결과 1건, 창 제목 일치를 모두 확인한 뒤에만 열지만, 확인이 맞았더라도 이미 일어난 읽음 표시를 되돌릴 방법은 없습니다.

설명서 html 만들기

설명서의 원본은 README.md 와 README.en.md 입니다. html은 아래 도구로 만들며, 손으로 고치지 않습니다.

powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Readme.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Readme.ps1 -Check

첫 줄은 html 두 개를 다시 만들고, 둘째 줄은 만들지 않고 최신인지만 확인합니다(다르면 종료 코드 1).

빌드 방법

컴파일하거나 묶는 빌드 단계가 없습니다. 스크립트 파일을 그대로 실행하고, C# 조각은 실행할 때 자동으로 컴파일됩니다. 문서의 html만 위의 tools\Build-Readme.ps1 로 만듭니다.

배포와 저장소 운영 (GitHub)

  • 저장소: GitHub의 비공개(private) 저장소입니다. 공개 전환은 소유자가 직접 결정하며, 공개 전에 개인 식별 정보(시험용 방 이름, 로컬 경로), 커밋 기록의 작성자 정보(GitHub가 합칠 때 만든 기록의 작성자에 계정의 공개 이메일 주소가 들어 있는 것을 확인했습니다), 카카오 약관 위험을 다시 점검해야 합니다. 기록을 다시 쓰는 작업은 하지 않았습니다.
  • 브랜치: 기본 브랜치 main 에 직접 올리지 않고, 작업 브랜치에서 풀 리퀘스트(PR)를 거쳐 합칩니다.
  • 올리지 않는 것: 세션 기록, 체크포인트(CHECKPOINT.md), 개발 도구 폴더(.remember, .sodam-re), 비밀 값(.env, 키 파일)은 .gitignore 로 제외합니다.
  • 줄 끝 규칙: .gitattributes 가 .bat·.cmd 는 CRLF, 나머지 글자 파일은 LF 로 고정합니다. 받은 PC의 git 설정과 상관없이 시험이 같은 결과가 나오게 하기 위한 것입니다.

개발 규칙 (자동 시험이 강제하는 것)

  • .ps1 은 UTF-8 BOM 포함, .bat 과 .cmd 는 BOM 없음 + CRLF. 파일을 쓴 뒤 tools\Write-Bom.ps1 -All 로 보정합니다.
  • throw 가 있는 모든 함수의 첫 문장은 $ErrorActionPreference = 'Stop' 입니다(호출한 쪽의 오류 설정 때문에 안전장치가 무시되는 것을 막기 위해서입니다).
  • 허용 키는 Ctrl+S, Ctrl+V, Ctrl+A, Ctrl+C, Enter 뿐이며 Esc 코드는 없어야 합니다.
  • 실제 카카오톡을 조작하는 시험을 켜는 스위치는 환경 변수 KAKAO_E2E=1 이지만, 아직 이 스위치를 쓰는 자동 시험은 없습니다. 지금까지의 실제 시험은 사용자가 시작을 알릴 때마다 따로 실행했고, 시험 방은 본인 혼자 있는 방만 씁니다(7단계부터).
  • 정적 분석(PSScriptAnalyzer)은 설치되어 있지 않아 실행하지 못했습니다.
